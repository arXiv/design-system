Questions for Deyan

2026-10-06. Six questions about the HTML papers renderer. They came up while moving decisions from the HTML paper mockup into the design system, and only the renderer can answer them. The first three matter most; the rest can wait.

Most needed

  1. Is what arXiv shows exactly what the author wrote? The design system shows the author's TeX and captions unchanged, in View TeX, Copy, the contents list and the figure viewer. Three places where that may not hold:

    • An equation's annotation in the sample paper has \displaystyle in aligned cells and braces such as R^{2}. If LaTeXML adds these, can it keep the author's original string?
    • A heading with math includes its TeX annotation in textContent, so a contents list built from it shows “Ψ\Psi”. Can LaTeXML give each heading a plain-text form, or should arXiv's scripts skip annotation?
    • Does a figure caption pass through with its label and punctuation (“Figure 1:”) exactly as written?

  2. Which ids stay the same? Permalinks need ids that last. Are these stable for a given paper version, including across LaTeXML upgrades?

    • paragraphs (S2.p3);
    • figures, display equations and bibliography entries;
    • each citation, so a reference can link back to where it is cited (“Cited by”).

  3. Can LaTeXML output this markup? The mockup made each of these by hand.

    • a <main> landmark round the paper, and a visually hidden “Abstract” heading;
    • footnotes: a marker linked to its note, and where that note is;
    • authors and affiliations, each author a separate element;
    • a scroll wrapper on every table, with role="region", tabindex="0" and a name from its caption;
    • a way to tell which figures have no alt text, so the page can say so.

Can wait

  1. Layout. Are display equations (table.ltx_equationgroup) layout tables, so a wide one can scroll as a block without losing anything for a screen reader? And can the bibliography, and anything after it, be a direct child of the page container, so arXiv can give it a full-width closing band?

  2. Stylesheets. Three things in the papers stylesheet:

    • Does production import ar5iv and the theme file into named cascade layers, as the mockup's copy does?
    • Can the bibliography's sideways overflow (a 10px indent on each entry and a stray 8px) be fixed there?
    • If ar5iv's own theme control still appears, can it use the same data-theme attribute and storage key as arXiv's theme.js, so there is one theme switch?

  3. Citations. A citation popover copies the bibliography entry whole. How often can a citation not find its entry? In that case the citation stays a plain link to the reference list.
