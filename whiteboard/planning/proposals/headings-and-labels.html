Headings and labels

A proposal for one rule that decides when content gets a heading and when it gets a panel label. Audit of the 24 docs pages, 30 September 2026.

The proposed rule

  1. A heading names something a reader would want to find. It has its own description, or it holds more than one example. It appears in the outline.
  2. A panel label names the one example directly below it. It has no description of its own. It stays out of the outline.
  3. A state label names one cell inside a demo, where variants sit side by side in a single card.
  4. Levels: h1 is the page title. h2 is a section, or a group heading (Modifiers, Rules, Spec). h3 is a part of a section, or a section under a group heading.

The test a builder applies: does a paragraph follow it, or does it cover several examples? Yes: heading. No: panel label.

No skipped levels on any page. The outline problem is that the same job is done two ways.

The same job, done two ways

  • A named part of a section, with its own description: colors.html uses h3 (Primary, Secondary, Warm tints). typography.html uses panel labels for the six typefaces (IBM Plex Sans, IBM Plex Mono…), and tags.html uses panel labels for its colour groups. A screen reader user can jump to "Warm tints" but not to "IBM Plex Mono".
  • Inside one page: colors.html uses h3 for Primary to Heritage, then panel labels for Text links and Focus indicators, which do the same job. It also uses panel labels for Recommended pairings and "Buttons change clothes on tinted surfaces", each followed by a description.
  • Surface variants of one example: cards.html names its internal and data-card demos with h3. Other pages name the same kind of demo with a panel label (header.html, dark-mode.html, tables.html).
  • Long labels: some panel labels hold a sentence, such as "Nothing selected — actions disable, they never disappear" (tables.html). In uppercase they are slow to read.

Rules on typography.html

  • The Panel label section says a label is not a heading so it stays out of the outline. That stays true. It needs the test above, so a builder knows which one to use.
  • "A label that a reader needs to navigate to is a heading" is already in the marginal note. The rule above makes that concrete.

Decisions

  1. Adopt the test: a paragraph follows it or it covers several examples, so it is a heading; otherwise a panel label.
  2. Surface variants of one example (public and internal) are panel labels, on every page.
  3. Panel labels stay short: a few words, no full sentence.
  4. Card titles inside demos stay h3, because they are the component's own content and a real page would have them.
  5. Apply the changes listed above in one pass, then regenerate the contents lists and digests.
