Inventory for a future "Papers" docs page. Read-only survey, 2026-10-05.

Sources: `H` = `whiteboard/mockups/public/html-phase1.html`, `A` = `whiteboard/mockups/public/abstract-phase2.html`. Line numbers are from those files today. "PG" = `whiteboard/planning/PROPOSED-GUIDELINES.md`. Docs paths are under `docs/`.

Classifications:
- **PAPER**: specific to presenting a paper; a candidate for the Papers page.
- **GENERAL**: would apply to any page; the target docs page is named.
- **RENDERER**: needs a change to LaTeXML output or the papers stylesheet that styles the body, so only the renderer's repo can do it.
- **ALREADY IN DOCS**: docs/ already states it (file named). Differences between mockup and docs are noted.

Two warnings before reading. First, in H a lot of CSS and script belongs to the retired "reader mode" (`body.mg-reader`, the `.arxiv-html-header` bar). The body never gets `mg-reader` (H:9395 says the toggle was removed), so that header, its compact state, its reading-progress bar, its full TOC dropdown and the centred PDF-style title block do not render in phase 1. Entries that depend on it are marked **(vestigial)**. Second, entries marked **(edit risk)** touch the rule that arXiv never edits, paraphrases or moves author content.

## 1. Metadata and hierarchy

- **1.1 [PAPER]** The HTML paper opens with an identity line above the title: arXiv ID with version, primary category code and its full name, the arXiv DOI link, and the license link. Where: H:4170-4177, `.new-watermark`. Reason: "evokes the watermark on the PDF first page"; "one tester missed the category when only the [gr-qc] code was shown"; "many readers land here directly without passing the abstract page". Described, not specified, in `sharing/html-papers.html`.
- **1.2 [PAPER]** The identity line replaces ar5iv's floating "arXiv:…" infobox, which is hidden. Where: H:1824 `#infobox`. Reason: same block as 1.1.
- **1.3 [PAPER]** Below 48rem the identity line puts ID/category and license on separate lines instead of letting them wrap. Where: H:1845-1858. Reason: "natural wrapping depends on content length and can leave the license trailing on the first line".
- **1.4 [PAPER]** The license appears as `<abbr title>` with a plain-words gloss of CC BY 4.0. Where: H:4177, H:4353; A:1025-1027, A:2074. Reason: "helps non-Western readers and AT users unfamiliar with Creative Commons naming conventions" (A). Note: H uses two different gloss texts for the same license.
- **1.5 [PAPER]** Top-of-paper order is title, date and version line, older-version warning, authors, abstract, on both pages. Where: H:4183-4216; A:1926-2019. No reason stated. (docs/papers.html sets a different order for listings, where formats sit with the dates.)
- **1.6 [ALREADY IN DOCS: spec/typography.md]** The paper title is the page's h1 and uses `clamp(1.375rem, 0.875rem + 2.4vw, 2rem)`, weight 700. Where: H:992-996, H:1667-1685; A:483-494. Reason: a fixed 2rem "wrapped a 7-word title onto five lines at 320px". Mockups use line-height 1.2; docs h1 is 1.25.
- **1.7 [PAPER]** The paper title fills the measure with `text-wrap: pretty`, overriding ar5iv's `balance` and its 52rem cap. Where: H:1668-1674. Reason: "Balance splits a two-line title into even halves… the title stops short of the column every other element uses." Conflicts with design-system.css:359, where the page h1 is balanced.
- **1.8 [PAPER] (vestigial)** The title and authors are centred and the abstract indented 12% "like the PDF"; below 48rem the indent becomes a light border. Where: H:1769-1810. Reason: "lowers the cognitive load when alternating between HTML and PDF versions". In phase 1 these are overridden to left-aligned beside the tools sidebar (H:420-436), so the PDF-like block is not what renders.
- **1.9 [RENDERER]** The "Abstract" heading is visually hidden but kept as an h2 for screen readers. Where: H:4212-4215 (`is-sr-only` added to LaTeXML markup). Reason: "visually redundant (readers recognize the lead paragraph), but kept for screen-reader navigation". The panel-label styling for `.ltx_title_abstract` at H:1712 is then dead CSS.
- **1.10 [ALREADY IN DOCS: version-display.html]** The date line shows Submitted, Announced (with time) and Revised "(this version)" in UTC, with `<time datetime>` and an `aria-hidden` dot plus sr-only comma. Where: H:4184-4188; A:1930-1937. Mockups match docs.
- **1.11 [ALREADY IN DOCS: version-display.html]** Version numbers follow the dates in mono; prior versions are links labelled "View version N"; the viewed version is bold, not a link, with `aria-current`. Where: H:4189-4194, H:727-733; A:1939-1941, A:504-527. Differences: mockups use `<span>` instead of `<strong>`, omit the sr-only ", this version", and A labels it "Version 3, current version".
- **1.12 [PAPER]** Version links on the HTML paper always point to `/abs/` pages, never `/html/`. Where: H:4190-4192. Reason: "an HTML rendering may not exist for a given version (no-TeX or failed-conversion papers), while the abstract page always exists."
- **1.13 [ALREADY IN DOCS: version-display.html, alerts.html]** An amber warning with the triangle icon appears only when viewing an older version: one sentence naming the version plus a link to the latest. Where: H:4196-4199, H:734-738; A:529-582, A:1944-1959. Differences: H uses `role="status"` and A no role, where docs require `role="alert"`; A's text "You're viewing" breaks the no-contractions rule; both use local classes instead of `.ds-alert`.
- **1.14 [PAPER]** Whether to show the older-version warning is decided server-side by comparing version numbers, never by parsing the Comments field. Where: A:539-543. Reason: "we explicitly chose NOT to parse Comments field since it's unreliable for version-change info".
- **1.15 [PAPER]** The date line and the older-version warning stay in the reading column near the title, and the full history goes in a sidebar accordion. Where: H:722-726. Reason: "so every reader (AT, mobile, citation-arrival) meets them near the title".
- **1.16 [PAPER] (edit risk)** The Version History accordion lists versions newest first, each with a tag (latest / viewing), a date, a one-line note, and a left rule, plus a "Full version history" link. Where: H:704-720, H:4296-4325. No reason stated. The notes ("Revised the scalar spectral-index discussion; corrected Eq. (4.7).") are arXiv-written summaries of what changed, which no source field supplies verbatim; that is paraphrase of author content.
- **1.17 [ALREADY IN DOCS: papers.html, progressive-disclosure.html, DESIGN-POLICIES.md Truncation]** Authors are an inline comma-separated list of links; the first 8 show, then a grey italic "… show all N authors" toggle, which becomes "show fewer". Where: H:1994-2043, H:4200-4205, H:7424-7445; A:584-697, A:1963-1987. Reason: "reads as a comma-separated paragraph visually but is a real list semantically for AT" (H). Difference: H marks it up as a `<ul>`, A as spans; H hides the tail without an `html.js` scope (H:2023), which breaks the no-JS rule A follows (A:638-643).
- **1.18 [PAPER]** Author lists have tiers: 1–8 all shown; up to 100 an inline toggle; above 100 a bounded scrolling region with a half-line peek, collapse buttons at both ends, and focus moved into it on open. Where: A:599-614, A:645-681, A:2413-2497. Reason: "inline expansion of 1000+ names dumps the reader into pages of links with the collapse control scrolled away; a modal or separate page adds a surface." The region's `aria-label` ("Full author list") omits the total that DESIGN-POLICIES requires.
- **1.19 [PAPER]** Metadata is a `<dl>`: Subjects (full name plus code linking to the listing), DOI, License, Journal (linked to its DOI), Comments, and on A the ancillary files; labels are the condensed uppercase panel label; Comments are shown verbatim. Where: H:4344-4366; A:1010-1063, A:2059-2105. Reason: "Screen readers announce 'description list, 5 items'". Labels differ: "DOI" (A) vs "arXiv DOI" (H); heading "Paper information" (A) vs "Paper Information" (H).
- **1.20 [PAPER]** Page widths for a paper: the abstract page uses a 920px content track (A:414-442); the HTML paper uses 850px above the TOC bar and narrows the body to 720px below it. Where: H:9174-9216. Reason (H): 720px is "about 92 characters… a negotiated point: at 510px roughly 30 of this paper's 100 display equations exceed the column, against 6 at 720px". Conflicts: DESIGN-POLICIES sets one 850px width per page and a ~510–590px long-form target; A's 920px matches neither.

## 2. Reading and typography

- **2.1 [PAPER]** The LaTeXML body is kept verbatim and arXiv styles it only through override CSS; ar5iv is loaded in a cascade layer, and the `arxiv-override` layer is used only where ar5iv sets `!important`. Where: H:25-34, H:108-118, H:1145-1147. Reason: "LaTeXML's DOM is the contract for selector specificity. If we restructure it, none of our overrides bind." This is the mechanical form of "never edit author content".
- **2.2 [PAPER]** The paper body is IBM Plex Sans at weight 400, replacing ar5iv's Source Sans at 300. Where: H:1641-1654, H:1720-1731. Reason: weight 300 was "a vendored default, not a decision… a Light weight can pass 1.4.3 numerically while being materially harder to read." (The family itself is in DESIGN-POLICIES.)
- **2.3 [PAPER]** Paper body text is 1rem with line-height 1.7, not the system's 1.5. Where: H:1656-1666, H:1733-1738. Reason: "this is long-form sustained reading, not reference copy." A's abstract text is 0.9375rem / 1.7 (A:882-888), so the two pages disagree on body size.
- **2.4 [PAPER]** Body text is left-aligned with `hyphens: auto` and `text-wrap: pretty`; it is not justified. Where: H:1739-1763. Reason: "CSS justification is not TeX justification… 70% of body paragraphs carry inline math… 357 unbreakable atoms"; WCAG 1.4.8. Still listed as open question 4 in `accessibility-research-questions.md`. H's own header comments (H:44, H:1647-1648) still say "justified body".
- **2.5 [PAPER]** Body text is Repository Brown at 400; a softer #4a433d was tried and rejected. Where: H:1725-1728. Reason: "the high contrast reads better, so no new stop is needed on the warm grey ladder."
- **2.6 [ALREADY IN DOCS: spec/typography.md heading scale]** Paper section headings are 1.5rem/600, subsections 1.25rem/600, line-height 1.25; acknowledgements, appendix and bibliography titles share the section size. Where: H:1695-1711.
- **2.7 [PAPER]** Section numbers are bolder (700) than the heading text. Where: H:1765-1767. Reason: "so the visual hierarchy stays legible even when the heading text is long."
- **2.8 [PAPER]** Figure captions are Plex Sans 0.875rem, left-aligned, full figure width. Where: H:2972-2983. Reason: "Centring a caption over a narrower measure… leaves the block ragged on both edges; a caption is prose about the figure, so it reads like prose."
- **2.9 [ALREADY IN DOCS: typography.html `.ds-annotation`; layout-patterns.html marginalia]** Footnote text and alt text shown in the margin use the annotation voice (Plex Serif italic, muted). Where: H:2786-2799. Docs describe this voice as "arXiv speaking quietly beside the author's text", while H says the right margin carries the author's own words (see 5.19).
- **2.10 [PAPER]** ar5iv's white background behind every image stays on paper figures and is cleared on chrome images, except funder logos. Where: H:263-282. Reason: "That is right for paper figures and wrong for chrome: a logo is an SVG that must sit on whatever bar it is in."
- **2.11 [PAPER]** LaTeXML's "experimental support / build logs" line and the beta badge are hidden. Where: H:1121-1126, H:9282-9301. Reason: "Our redesigned footer carries the same affordances in a cleaner form." (sharing/html-papers.html: "No 'test' or 'experimental' framing.")
- **2.12 [ALREADY IN DOCS: DESIGN-POLICIES.md Colors; dark-mode.html]** Dark mode is live on the HTML paper, and the ar5iv theme switch is mirrored through `data-theme`. Where: H:1096-1106, H:3592-3655. Conflicts: A forces `color-scheme: light` and `background: #fff` (A:74-80, A:106); H's header comment (H:54) still says "Light-mode-only force".
- **2.13 [PAPER]** Print: chrome hidden, the references band flattened, no page breaks inside sections, equations, tables or figures, none after headings, identity line at 10pt. Where: H:3391-3457, H:9231-9244; A:1773-1822. Reason: "Strip the sticky chrome and popover infrastructure for print." (Print-always-light is already in design-system.css.)
- **2.14 [GENERAL → links.html]** In print, external link URLs are written out after the link text; in-page anchors are not. Where: H:3450-3456; A:1815-1821. Reason: "so paper printouts retain link information. Internal anchors are not expanded — too noisy."
- **2.15 [RENDERER]** The bibliography's horizontal-overflow bug is fixed by moving the 10px indent onto the number cell and clipping a phantom 8px. Where: H:1891-1918. Reason: "Upstream defect, not ours, and it is live on arxiv.org today… it belongs upstream in the papers stylesheet."

## 3. Navigation inside a paper

- **3.1 [ALREADY IN DOCS: progressive-disclosure.html TOC bar; DESIGN-POLICIES.md Chrome]** The paper's one sticky element is a centred "Contents" bar below a site header that scrolls away; it is frosted at 92% (96% when stuck). Where: H:739-800, H:4379-4440. Differences: the mockup's trigger is a scripted `<button>` where docs use `<details>`; it does not set `aria-current="location"`; its list is hand-written, top-level only, and its titles do not match the paper (H:4411-4415).
- **3.2 [PAPER]** The left slot of the contents bar holds a one-colour Library Grey arXiv logo linking home (a light variant in dark mode). Where: H:4386-4401, H:777-781. Reason: "Once the reader scrolls, this bar is the only chrome on screen — most readers arrive at papers from search and links, and nothing else says where they are."
- **3.3 [PAPER]** The right slot of the contents bar holds Abstract, PDF and TeX Source links, each an icon plus a label. Where: H:4419-4438. Reason: "the abstract page stays the paper's canonical home, so the route back rides in the always-visible tools bar."
- **3.4 [PAPER]** When the bar is stuck, or below 48rem, the tool labels hide, except "Abstract", which keeps its label when stuck. Where: H:787-800. Reason: "a bare ← reads as browser-back, and no icon unambiguously means 'abstract page'. The PDF / TeX glyphs survive compaction because they're recognizable format marks."
- **3.5 [PAPER]** TeX Source is shown as a typeset TᴇX wordmark (aria-hidden) with the label "Source" and sr-only "TeX source". Where: H:1570-1583, H:3705-3712, H:4433-4437. Reason: "Keeps the nav text-only."
- **3.6 [PAPER]** The PDF link in the paper's chrome opens a new tab and says so to screen readers. Where: H:3698-3704, H:4428-4432. Reason: "so the user doesn't lose their position in the HTML reader." The PDF button in the tools sidebar (H:4239) does not open a new tab.
- **3.7 [ALREADY IN DOCS: progressive-disclosure.html TOC bar]** The trigger reads "Contents · <current section>" (cut at 64 characters) and the current entry is highlighted. Where: H:9476-9504, H:872-874.
- **3.8 [PAPER]** The permanent LaTeXML left sidebar is removed; its TOC stays in the DOM, visually hidden, as the data source and for no-JS screen-reader users. Where: H:1235-1252, H:1548-1568, H:2751-2757. Reason: "10+ GitHub UX issues asking to hide, collapse, or fix the sidebar's friction… Frees the left margin for arXiv-layer chrome."
- **3.9 [PAPER] (vestigial)** A TOC built from the LaTeXML TOC strips MathML annotations from section titles, indents by depth, and treats abstract, appendix and bibliography as top level. Where: H:1414-1423, H:3863-3882. Reason: unstripped titles showed "Evolution of Ψ\Psi and Φ\Phi". Only the hidden header uses this; the live bar's list has no subsections, appendices or references.
- **3.10 [PAPER] (vestigial)** At narrow widths the TOC becomes a full-screen menu with a visible close, 44px rows, `dvh` height and a bottom fade. Where: H:1435-1504. Reason: "a tester could not scroll to the END of the ToC on their phone". In PG G6 and G10; the half-item peek follow-up named in G10 is not done.
- **3.11 [PAPER] (vestigial)** The reader header compacts from 52px to 36px after the abstract, and narrow widths reuse that compact state. Where: H:1128-1143, H:1506-1534, H:1585-1609. This is PG G2 and G3.
- **3.12 [PAPER] (vestigial)** A 2px Link Blue reading-progress bar (`role="progressbar"`) and a "N min read / N min left" label are shown; reading time assumes ~200 wpm and excludes the references; neither announces on scroll. Where: H:1611-1629, H:3717-3721, H:3739-3805. Reason: "researchers don't sit and read those" (references). Silence is PG G9. The label element does not exist in the markup, and docs/PATTERNS.md still lists "a reading indicator" as part of the reader chrome.
- **3.13 [ALREADY IN DOCS: DESIGN-POLICIES.md Chrome; design-system.css `html:has(.ds-toc-bar)`]** Every anchor jump lands 80px below the top of the viewport (`scroll-padding-top`). Where: H:1108-1119. Docs use 5rem. This is PG G1.
- **3.14 [PAPER]** There are two routes back to the abstract page: a quiet "Back to abstract" button above the identity line, and "Abstract" in the contents bar. Where: H:4145-4169, H:653-665. Reason: "the abstract page is still the paper's canonical home"; "the button form was kept deliberately: the route back is load-bearing while two pages exist" (it costs 52px). H:648-652 says it moved into the sidebar as text, which contradicts the markup. It uses `.mg-btn-quiet` (Card Grey fill), where buttons.html settled the quiet tier as `.ds-btn-text` (no fill).
- **3.15 [PAPER]** Abstract and full paper on one page as the default, with the separate abstract page retired. Where: H:4156-4159, H:9395-9396, H:965-972. Reason: "If it is the default there is no second page to go back to, this control retires, and the page is best-in-class on every measure in the audit." This is a proposal; A is still a separate page.
- **3.16 [PAPER]** A second, in-context skip link ("Skip past document tools to paper content") sits before the tools sidebar, in addition to the page skip link. Where: H:475-492, H:4219-4224. Reason: "a more specific 'skip past document tools to paper content' jump". (The page-level `.ds-skip-link` is in header.html.)
- **3.17 [ALREADY IN DOCS: links.html `.ds-anchor`]** Every section, subsection and appendix heading gets a control that copies its link, with the section title in its accessible name. Where: H:3228-3258, H:3554-3560, H:8655-8700. Conflict: docs use an icon-only button after the heading that stays visible on touch; H uses a margin pill with the word "Permalink" that touch users reveal by tapping. - **3.18 [PAPER]** Hovering or tapping a paragraph shows a faint scope rule and a sticky "Permalink" pill in the left margin; it copies `#S2.p3` and confirms "Copied ¶ 2.3 ✓"; its accessible name carries "§2 ¶3". Where: H:3459-3590, H:9572-9676. Where: H:3474-3482. ## 4. Figures, tables and equations

- **4.1 [PAPER]** Each display equation is wrapped in a region that shows a hairline border on hover, focus or tap, and a white pill straddling its bottom edge with View TeX, Copy and Permalink, without layout shift. Where: H:2353-2452, H:2526-2567, H:7965-8187. Reason: "No layout shift: padding is small and equal at all times; only the background tint and chip opacity change." The pill matches `.ds-element-pill` (buttons.html) but uses local `.eqn-chips`. H's comments (H:2356-2370, H:7971-7978) still describe four chips in a vertical left-margin column.
- **4.2 [PAPER]** View TeX swaps the rendered equation for plain monospace TeX in place, with no code box. Where: H:2629-2648. Reason: "the bordered block read as unnecessary chrome — the monospace face and the toggle context already say 'source'."
- **4.3 [PAPER]** Copy copies what is on screen (MathML in math view, TeX in TeX view), and sits next to the toggle. Where: H:2372-2379, H:7984-7985. Reason: "copy depends on the toggle state — proximity makes the relationship clear."
- **4.4 [PAPER] (edit risk)** Copied TeX has LaTeXML's `\displaystyle` removed; copied MathML has `id`s removed. Where: H:8023-8044. Reason: "noise for reading and for pasting back into a document (the user's own math environment determines the style)."
- **4.5 [PAPER]** Inline math gets no arXiv affordance, tabindex or ARIA. Where: H:236-239, H:2381-2382, H:7992-7994. Reason: "The browser+AT path handles inline math via native MathML and Intent annotations."
- **4.6 [PAPER]** No MathJax, no speech engine and no read-aloud on the paper; screen readers read the native MathML. Where: H:187-240. Reason: Deyan Ginev's "MathML Core + Intent direction routes around them [SRE misreadings] entirely"; Listen was "too much complexity for phase 1." Conflicts: docs/accessibility-priorities.md still says "MathJax for visual rendering" and names SRE; H:81-85 still says "We ship MathML + MathJax".
- **4.7 [PAPER]** MathML TeX annotations are never displayed, and the TeX view is hidden by default. Where: H:924-934. Reason: ar5iv "is missing the default-hide rule… the TeX source leaks under every equation."
- **4.8 [PAPER]** Below 1200px a wide equation scrolls inside its own box, and its number stays pinned at the right edge. Where: H:2454-2493. Reason: "tags like '(4.7)' sat beyond the initial viewport on 119 of 145 equations at 320px." The scroll box has no `tabindex` or name, which DESIGN-POLICIES (Truncation) requires.
- **4.9 [PAPER] (part RENDERER)** Content that cannot reflow gets its own horizontal scroll: tables (on the LaTeXML `.ltx_table` wrapper, never the `<table>`), preformatted blocks, and display equations. Images scale instead. Where: H:2304-2351. Reason: overflow on the table box would "strip the table semantics assistive technology reads"; "A tabular with no wrapper… the fix for that belongs in the HTML." The principle is in DESIGN-POLICIES and tables.html (`.ds-table-scroll`); the paper version again lacks `tabindex`, role and name.
- **4.10 [PAPER]** Each figure gets the same reveal: a border around the image and a pill on the image's bottom edge with Expand, Permalink, and at narrow widths Alt text or How to add alt text. Where: H:2888-3067, H:8449-8650. Reason: "Same wide/narrow split as formulas and footnotes."
- **4.11 [PAPER]** The author's alt text is shown to sighted readers in the right margin under an "Alt text" label; the image's alt attribute is never changed. Where: H:2888-2905, H:3156-3177, H:8603-8620. Reason: "the alt attribute is whatever the author wrote. arXiv's role here is making it visible, not authoring it."
- **4.12 [PAPER]** A figure without alt text shows "No alt text provided" and a "How to add alt text" link, and the notice is not hidden from screen readers. Where: H:8621-8642, H:3051-3063. Reason: "Screen readers' own signals for a missing alt attribute are unreliable… the guidance link's primary audience is authors — including blind and low-vision authors." Conflicts with accessibility-priorities.md "present-only — no 'missing' indicators".
- **4.13 [PAPER]** Reader- or AI-contributed alt text is not offered in phase 1. Where: H:2900-2905, H:8607-8613. Reason: "harvesting community/agent alt text needs annotation storage and moderation backends, deferred."
- **4.14 [PAPER]** Figures open in a viewer: native `<dialog>` (`.ds-modal--wide`, `closedby="any"`), zoom that persists until closed, wheel/buttons/double-click/pinch/keyboard zoom, drag to pan, zoom level announced, focus returned to the opener, figure cloned (never moved) and rendered at 2×. Where: H:3260-3364, H:8702-8993. Reason: figure viewing is "the DOMINANT theme in the open html_feedback queue"; "Zoom PERSISTS until explicitly closed — the #1 complaint about the current hold-to-view behavior"; native dialog "kills the entire z-index bug class". The dialog shell is already in modals.html.
- **4.15 [PAPER]** Clicking the image opens the viewer (zoom-in cursor), and an Expand chip is the visible keyboard path. Where: H:3354-3358, H:8964-8990. Reason: issue #1372, "Tried to enlarge… No luck. Expected image to pop out as on other sites."
- **4.16 [PAPER] (edit risk, minor)** The viewer title is the caption's bold "Figure N" with its trailing period removed; the caption is a clone. Where: H:8954-8957. No reason stated.
