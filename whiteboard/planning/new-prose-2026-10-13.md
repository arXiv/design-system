## header.html

- Rules: "No breadcrumbs. arXiv's sitemap is wide and shallow, so the header navigation and the secondary navigation show the reader's place. A tool's main pages, such as its starting page, are links in the header navigation; the way back is there, not in a link above the page heading."
- Two levels of navigation, `<h1>`: "Follows the reader's choices: the open section, then the filters, in that order, such as "Submissions and holds, all of cs" or "Moderators, cs.DC". The reader knows where they are without breadcrumbs."
- Internal header: "Every internal tool uses an internal logo, not the public one, so the reader can tell they are in an internal tool."

## layout-patterns.html, The main content comes first

- "A line that sets the data in context, such as the period it covers and when it was last updated, goes there, just above the main content. A refresh control and an explanation of the figures are secondary: put them below the main content or in an accordion."
- "A page with little on it needs no section headings. The page heading names it; a heading such as "Subject groups" under "All sections" adds nothing."
- "A link in the header navigation is not repeated on the page, and no link on the page repeats the page heading."
- "One name for one thing. Choose one word for each kind of thing, such as "section", and use it in every heading, link and sentence."
- "…, and neither do the lighter pages of the same tool, so every page of the tool looks the same."
- Elsewhere: "No breadcrumbs. See Header, Rules."

## pager.html

- "Above and below a long list; below a short one. A list or table of more than about 25 rows has the pager above and below it, so a reader at the end can go on without scrolling back up. A shorter list has the pager below it only."

### layout-patterns.html, The page container (moved from DESIGN-POLICIES and shortened)

- "One width per page. Prose, tables, demos, code and callouts share the reading column, so everything on a page has the same left and right edge. A page that needs a different width changes the width token; it does not add a second width."
- "Long-form reading is narrower. An abstract, a paper body or an explanation read from start to finish targets a line of about 65 characters, set on the page, not on the paragraph."
- "Reference pages accept a longer line. At 850px a line is about 109 characters. That suits short reference paragraphs and two-column layouts; it is not a reason to set long text that wide."
- "Few breakpoints, each for a change in structure. Prefer a layout that needs no query, then a container query, then a media query. Breakpoints about text are in rem; breakpoints about fixed widths are in px. A threshold that CSS and JavaScript share is a custom property, read by the script with `getComputedStyle`."

### using.html, Internal tools

- "Internal tools are compact. `.ds-internal` also sets less padding inside buttons, fields, table cells and cards, through the density tokens (…), so a dense screen holds more. There is no compact class: the density comes with the surface."
