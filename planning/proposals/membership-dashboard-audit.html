Membership dashboard audit

Step 1 of the dashboard work: what Christopher's screens for dev.arxiv.org/activity/ use, how each element maps to the design system, and what the design system should change or add. The rebuild comes after these decisions.

Summary

  • The table header is too quiet for dense data. Ours is 11px Library Grey on Card Grey, 5.12:1. Christopher's is larger and Repository Brown on the same grey, 15.22:1. Recommendation: change the default header, not add a variant.
  • Most of his page is built from parts we already have. Header, footer, cards, card grid, tags, buttons, fields, sortable tables and the warning and error tints all exist.
  • Four things are missing: tabs, a stat card (a label and a big number), a meter (a bar or a range against an average), and a colour legend.
  • Several differences come from an older copy of the stylesheet. The footer dots are faint and the account area shows a name and Log out, both changed since. Pulling the current stylesheet fixes those.

Should a table always have a border all the way around?

Recommend: yes, one rule with one exception that comes from the markup.

  • Always framed. A table without a header row has no tinted row to mark its top edge; the frame gives every table the same edge.
  • Inside a card, no frame. The card is already the frame. The stylesheet can drop the table's border when the table sits directly in a card, so nobody chooses it.
  • Christopher's table has no side frame. It works on his page because the header row is tinted and the table fills the width. It would not work for a table without a header row.

What the design system should change or add

  1. Table header, stronger by default (option B). Small change, helps every table.
  2. Table frame rule: always framed; no frame directly inside a card.
  3. Tabs for views on one page, separate from .ds-subnav, which links between pages.
  4. Stat card: a label and a large number, built on .ds-card.
  5. Meter: one component for the progress bar and the range gauge, with a threshold state that adds an icon.
  6. Legend: swatch and label pairs, for any colour that marks data.
  7. Tinted cells by value: document when a cell or column takes the warning or error tint.

Depends on the parallel proposals

  • Tints (planning/proposals/tints.html): tinted threshold columns, the legend swatches, the table header grey, tab backgrounds.
  • Headings and labels (planning/proposals/headings-and-labels.html): blue headings and card titles, uppercase tab labels, stat card labels, the "Threshold Days:" label.

Decisions

  1. Table header: change the default to option B, or keep today's and add a variant?
  2. Table frame: always framed, except directly inside a card?
  3. Build tabs as a new component, and should the rebuild allow two levels?
  4. Add a stat card, a meter and a legend to the design system?
  5. Headings in Archival Blue: allowed on internal tools, or text colour everywhere? (Headings proposal.)
  6. Outlined fields with the label in the border: adopt, or keep labels above?
