PROPOSAL — one header component

Status: proposal, 2026-09-29. Nothing on this page is in the stylesheet. Classes named .proposed-* are sketches.

The short version

  • All three headers already share three regions: a logo, navigation, and an account area. The public bar and the docs bar are already one component (.ds-site-header, with --light for the docs). The Admin Console bar is a separate build that does the same job.
  • Propose one component with three named regions, plus one optional region for tools. Logo, navigation, tools (optional), account. Every header uses the same markup order.
  • Variation comes from two places only. Modifiers choose the surface (--light) and where the navigation sits (--nav-start). Tier 2 re-points the header tokens and supplies the tool's wordmark. Tier 2 never adds layout rules.
  • Five Admin Console patterns do not fit today. Two are worth adding (navigation beside the logo, a search field in the bar). Three should change (the sticky bar, the sidebar button in the header, and navigation items that are buttons with nothing behind them).

3. Proposed anatomy

One markup order for every header. The regions are always in this order, so a reader, a screen reader and a stylesheet all find the same thing in the same place.

RegionClassHoldsRequired
Logo.ds-site-header-logo (exists)Logo image, or a property's text wordmarkYes
Navigation.ds-site-header-nav (exists)Links and dropdown menus. It is the <nav> landmark, so it holds site sections only.Yes
Tools.ds-site-header-tools (new)Search field, theme control, icon buttons that act on the whole toolNo
Account.ds-site-header-account (new)Log in, or greeting + Account menu. Moves out of the <nav>: an account menu is not a site section.On any property with accounts

Modifiers (tier 1)

  • .ds-site-header--light (exists): the white surface, by re-pointing the seven --ds-hdr-* tokens.
  • .ds-site-header--nav-start (new): the navigation sits beside the logo, and the free space falls after it instead of after the logo. For tools where moving between sections is the main job of the bar.

What tier 2 may change

  • The --ds-hdr-* token values (hover wash, focus ring), the same way it re-points other tokens.
  • Nothing else. No layout rules, no new parts. A tool that needs a new part proposes it for tier 1.
  • Content is not styling: each tool chooses its own links, tools and wordmark image.

5. Decisions for Shamsi

  1. Regions. Adopt logo · navigation · tools · account as the one anatomy, with tools optional?
  2. Account out of the <nav>. Move the account area to its own region on arxiv.org too? It changes no pixels; it changes the landmark.
  3. Navigation beside the logo. Add --nav-start for internal tools, or keep every header's navigation on the right?
  4. Search in the bar. Allow one search field in the tools region for internal tools? One field with a scope choice, or two fields?
  5. Sticky admin bar. Drop the sticky behaviour, or ask the design team to name internal tools in the sticky rule?
  6. Refresh and sidebar buttons. Move them out of the header (refresh to the data's toolbar, the sidebar toggle to the sidebar)?
  7. Name in the account area. Internal shows the full name as the Account menu's label, and public keeps the first-name greeting?
