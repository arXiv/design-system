Bulk-action bar in tier 1

Proposal, 2026-09-29. The bar can move to tier 1 without choosing any new colours: it has no fill of its own, and every colour it shows is already a tier 1 token with a public default. The lime you see on internal pages comes from the selected rows and the row checkboxes, not from the bar. One internal colour fails contrast and should change. One decision is open: whether the bar takes a tint while rows are selected.

2. Proposal

  • Move to tier 1: .ds-bulk-count and .ds-filter, unchanged.
  • Name the bar: a new .ds-bulk-bar wrapper replaces .ds-btn-group--split and the inline style. It gives the destructive action its gap and gives the component a name that agents and developers can search for.
  • Public colours are the existing tier 1 defaults: Active Wash (--ds-blue-50, from Open Blue) on selected rows, Link Blue checkboxes, Library Grey count, UI Boundary Grey filter underline, and the button tiers.
  • Internal colours come from .ds-internal, which already re-points the accent tokens. Nothing in the bar needs an internal rule of its own.
  • Fix the internal checkbox: tier 2 ticks row checkboxes in Access Lime Border (#9cb522), which is 2.32:1 against white, under the 3:1 a control needs. Access Lime Deep (--ds-accent-border-active, #6b7a10) is 4.75:1 in light and 3.12:1 in dark. The same change applies to .ds-check, which uses the same colour.

Option A (recommended): the bar stays neutral

This keeps the current rule. The selected rows carry the tint, and the bar reads as ordinary controls above the table. The primary button keeps its full contrast with the page.

Option B: the bar takes the selection tint while rows are selected

The bar fills with the same --ds-accent-wash as the selected rows, but only while at least one row is selected (.is-active, set by the script that updates the count). This ties the bar to the selection. The cost: the primary button is Open Blue on Active Wash, so its shape blurs into the bar on public pages; its label still reads. This reverses the current “bar stays neutral” rule.

3. Contrast

Text needs 4.5:1 and a control boundary needs 3:1 (WCAG 1.4.3 and 1.4.11). The tint on a selected row is never the only signal, because the checkbox carries the state, so the tint itself has no minimum.

5. Decisions

  1. Option A or Option B. A keeps the current rule and needs no new colour. B tints the bar while rows are selected.
  2. The name .ds-bulk-bar. The alternative is to keep .ds-btn-group--split and add only a rule for the destructive gap, which means no new class but no searchable name either.
  3. The internal checkbox colour. Access Lime Deep in place of Access Lime Border, for row checkboxes and .ds-check.

Not changed here: the filter’s chevron is a fixed grey drawn in the SVG (#8b8680), not a token, so it does not follow the theme. It reads on both grounds today; it is noted for when the filter moves.
