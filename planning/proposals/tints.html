Tints, borders and space

Proposal, 30 September 2026. The system uses about twenty different background fills today. Most of them do one of five jobs. This page lists every fill, proposes five tint roles, and proposes one rule for when a group of content gets space, a tint or a border.

2. Borders and hairlines used for grouping today

  • Full border, 1px Border Light: card, table, note, alert (plus a 4px start edge), input.
  • One edge: data card (4px Open Blue top), secondary navigation (bottom), TOC bar (top), site footer (top), modal footer (top), divider <hr>.
  • Hairlines between items: data card rows (the grid gap shows Border Light), table rows (Card Grey), the table header row (bottom).
  • Nothing: the sidebar and its blocks, the stepper, button groups, the bulk-action row. These are grouped by space alone.

3. Proposal: five tint roles

Every fill becomes one of five roles. Each role has one token. A component picks a role; it never picks a colour.

RoleTokenMeansLightDark
Page--ds-canvasThe ground everything sits on. Also row headers, row hover and stripes inside a white table.Warm WashRepository Brown
Surface--ds-surfaceAn object the reader works with: card, table, field, dialog, menu.White#2b2723
Reference--ds-surface-mutedRead-only or structural content: data card, table header, note, tag, secondary zone.Card Greynew value, distinct from Surface (see decision 5)
Accent--ds-accent-surfaceSelected, current, or floating over the page: selected row, current TOC item, popover, tooltip, essential note.Tint Light (Access Lime wash inside .ds-internal)#132433 (lime dark inside .ds-internal)
Statusthe four --ds-*-bgA state: info, success, warning, error. Alerts, status tags, segmented buttons only.four washesfour dark values

Chrome (Repository Brown bars and code blocks), the modal scrim, and the text-colour washes for inline code, disabled controls and hover are not tints: they stay as they are. Active Wash stays for pressed and hover states of controls only. --ds-table-selected goes; a selected row uses the Accent role.

4. Proposal: always, never or optional

Always tintedNever tintedOptional (a modifier)
Page (Page role). Data card, table header row, note, tag (Reference). Popover, tooltip, selected row, current item (Accent). Alert, status tag (Status). Card, table body, field, dialog, menu, secondary navigation, stepper, button groups. Page zones (.ds-zone-secondary). Striped rows (.ds-table--striped). Nothing else.

A component decides its tint once, in the design system. Two optional tints is the whole list. A new optional tint needs a real page that fails without it.

5. Proposal: space, tint or border

  1. Space groups. Items that belong together sit closer than items that do not. This is the default and needs no drawing.
  2. A tint says what kind of content it is. Reference, status, selected. It is not used to mark where a group ends.
  3. A border marks the edge of one object the reader handles as a whole: a card, a table, a field, a dialog. It also marks the edge of a region that sits beside other content and has no tint.

The sidebar under this rule

The sidebar is a region beside the reading column with no tint, so rule 3 gives it a border: one hairline on its inner edge, beside the reading column, and on its top edge when it moves below the content. Its blocks stay separated by space.

A tinted sidebar was tried when the sidebar was built. A data card inside a Card Grey sidebar lost its edges. A Warm Wash tint avoids that clash in light mode but is very close to Card Grey, and in dark mode it is the page colour, so the sidebar would look like a hole in the white band.

The stepper under this rule

The stepper is one control, not a region, so it takes no line. With text-only buttons (proposed separately) and 24px below it, Previous, the count and Next read as one row. A dashed line would add a line style the system does not have.

Tables under this rule

A table is one object, so it always has a border all the way around. That matches today.

6. Decisions

1. Five tint roles

Adopt Page, Surface, Reference, Accent and Status as the only tint roles, one token each. Recommended.

2. Selected uses Accent

Retire --ds-table-selected; selected rows, the current TOC item, popovers and tooltips all use Accent. Active Wash stays for pressed and hover states only. Recommended.

3. Always, never, optional

Adopt the table in section 4, with only two optional tints (page zones, striped rows). Recommended.

4. Space, tint, border

Adopt the three rules in section 5 and write them on spacing.html, replacing "You do not need a border, really". Recommended.

5. A dark value for Reference

Give --ds-surface-muted its own dark value so data cards, table headers, notes and tags stay distinct from cards in dark mode. Recommended; the value needs a contrast check.

6. Sidebar

A hairline on the sidebar's inner edge (top edge when stacked). Recommended over a tint and over space only.

7. Stepper

No line under the stepper; text-only buttons and the 24px gap group it. Recommended over a dashed or solid line.

8. Tables

A border all the way around, always. Recommended; no change from today.
