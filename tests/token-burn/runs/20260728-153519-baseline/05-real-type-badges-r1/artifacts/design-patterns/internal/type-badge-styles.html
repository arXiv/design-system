Submission Type Badges

Color-coded inline labels used in arXiv Check and the Admin Console to identify a submission's type at a glance. The four types — new, replacement, withdrawal, and cross-listing — are defined in design-system.css and appear primarily in moderation queue tables.

These are internal-tools-only components. They use Access Lime family colors as context signals (not for the badges themselves) and appear on the warm Warm Wash background (#f9f7f7) that is the internal tools page background.

Variants

The complete set of submission type badges. Apply .type-badge (base shape and typography) plus one modifier class to a <span>. Text labels are the primary signal — color is a redundant visual aid.

Four types, no more. New, Rep (replacement), Wdr (withdrawal), and Cross (cross-list) are the complete set of arXiv submission types as of 2026-07-28. Do not introduce additional badge classes without adding them to design-system.css with a verified contrast check and an entry in this reference page.
Color is not the sole signal (WCAG 1.4.1). Each badge carries an abbreviated text label as its primary identifier. Color is a learned secondary cue for staff familiar with the palette. This means the badges remain meaningful in grayscale, in forced-colors mode, and for users with color vision deficiencies.

Column width: A Type column of 68px accommodates all four badge labels ("Cross" is the longest at ~38px rendered) with comfortable horizontal breathing room. Using a fixed width prevents table reflow when the queue is filtered.
Filter integration: Use .ds-filter with option values that match badge text ("New", "Rep", "Wdr", "Cross"). Always include an "All" option as the inclusive default (required by DESIGN-POLICIES.md Filter dropdown rule).

Color tokens

Each badge uses three color values: background, border, and text. Values are specified directly in the .type-new / .type-rep / .type-wdr / .type-cross rules in design-system.css — not as CSS custom properties, because the set is small and stable.

Palette relationships — each badge family maps to a semantic register already established in the design system:
  • .type-new — blue, from the same family as .seg-neutral and .ds-alert-info. Signals "standard intake / informational."
  • .type-rep — amber/yellow, from the same family as .ds-alert-warning. Signals "requires attention — content has changed."
  • .type-wdr — dark warm-grey, the heaviest visual weight. Signals "terminal action — paper removed from circulation."
  • .type-cross — warm light-grey, the lowest visual weight. Signals "ancillary routing action, no change to the paper itself."
Border contrast. Badge borders are decorative — they help distinguish adjacent same-colored cells and add definition at the edge of the fill. They are not the sole visual boundary of an interactive element, so they are not required to pass the WCAG 3:1 non-text contrast threshold (WCAG 1.4.11). The functional element is the text label; text contrast against the fill background is verified above. The fill-on-page-background contrast is not a WCAG requirement for non-interactive labels.

Typography and shape

Badges use IBM Plex Mono at 11px — the same mono stack used for arXiv IDs, DOIs, and other system-assigned identifiers. Mono signals "this is arXiv's classification, not author-supplied content."

Base styles: 11px / font-weight 400 / IBM Plex Mono (falls through to SF Mono, Fira Code, system monospace). Border-radius 3px — intentionally tighter than the 6px used for buttons, so badges read as labels rather than interactive controls. Padding 1px 6px to keep badges compact and row-height-neutral in tables.
Display: display: inline-block. Badges are inline by default and work inside <td>, headings, and running text without disrupting layout. white-space: nowrap prevents line breaks inside the label.

HTML usage

Always apply both the base class and the modifier. Use a <span>, never a <div>.

Markup

<!-- Base + modifier on a <span> -->
<span class="type-badge type-new">New</span>
<span class="type-badge type-rep">Rep</span>
<span class="type-badge type-wdr">Wdr</span>
<span class="type-badge type-cross">Cross</span>

<!-- Inside a table cell (typical use) -->
<td><span class="type-badge type-new">New</span></td>

<!-- With a screen-reader expansion when no column header provides context -->
<span class="type-badge type-wdr">
  Wdr<span class="sr-only"> (withdrawal)</span>
</span>
Screen readers. The abbreviated text ("New", "Rep", "Wdr", "Cross") is the accessible label. In a table with a "Type" column header, no additional aria attributes are needed — the header provides sufficient context. If a badge appears outside a table (for example, in a page heading or a detail panel), add a visually-hidden expansion via .sr-only so that the full meaning is available to assistive technology: Wdr<span class="sr-only"> (withdrawal)</span>.
Not interactive. Type badges are read-only labels, not buttons or links. Never add role="button", tabindex, or click handlers to a .type-badge. If a badge needs to be clickable (e.g., to filter by type), wrap it in a <button> or <a> with its own accessible label.
Dark mode (pending). The .type-new, .type-rep, and .type-cross badges use light fills that read poorly on a dark background. Dark mode overrides are not yet defined in design-system.css. When adding them, follow the same pattern as the alert token overrides inside the @media (prefers-color-scheme: dark) block: define dark-surface background, border, and text values for each variant, verify all text contrast ratios at 4.5:1 minimum, and remove data-theme="light" from this reference page.
