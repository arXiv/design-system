Dataset & Code Links Card

The .ds-artifact-links component — a card listing a paper's external research artifacts (datasets, code repositories, supplementary material) on the abstract page. Reads as browsable supplementary material, not a primary call to action. All styles are live from design-system.css.

Added 2026-07-28. See also: button styles, alert styles.

Single artifact

The minimum case — one row. The card scales naturally to its content; no overflow control is needed.

Multiple artifacts — within threshold (1–6 rows)

Up to 6 rows show at native height. No overflow, no scroll, no truncation signal needed. The count badge in the heading is optional — useful when the consumer wants to telegraph the total upfront.

Overflow — 12 artifacts (7+ rows)

When the list exceeds 6 rows (approximately 272px), overflow-y: auto kicks in. The last fully visible row is followed by roughly half of the next row — the half-item peek — which is the geometric signal that the list continues. The <ul> carries tabindex="0" so keyboard users can Tab into the region and scroll with arrow keys, and aria-label="12 research artifacts" so screen-reader users know the total without scrolling to discover it.

Design decisions

Every decision traces back to a policy or palette rule.

Decision Value / treatment Policy source
Primary surface White #fff — same as the abstract page body color-mapping.md: "Page background: White #ffffff — clean reading surface"
Card border --arxiv-border-light #ddd8d2 — decorative hairline color-mapping.md: "Component hairline borders — inputs, toggle tracks, card edges. Decorative only (below 3:1); not for sole interactive boundaries."
Row separator Same --arxiv-border-light token — consistent hairline Same as above; these borders are decorative, not interactive boundaries
Row hover fill --arxiv-card-grey #f0eeec color-mapping.md: "Card surface / hover fill — Card Grey"
Label text (artifact role) 13px / weight 500 / --arxiv-ink #1c1a17 typography.md type scale: body text 15px, secondary 13px / 400–500
Destination column 11px uppercase condensed / --arxiv-grey #6b6459 (5.83:1 ✓ AA) typography.md: "Metadata labels — 11px uppercase / 600 / Plex Sans Condensed"
Link color --arxiv-link-blue #1565c0 with underline (5.74:1 on white ✓ AA) DESIGN-POLICIES.md: "Inline links in body text must be underlined." color-mapping.md link tier.
Link hover --arxiv-link-hover #1050a0 (7.83:1 ✓ AAA) color-mapping.md: "Link Hover — link hover state"
Visited link --arxiv-link-visited #7b2fbe Visited Purple (7.02:1 ✓ AAA) color-mapping.md: visited link state; DESIGN-PROGRESS.md: "visited memory aids researchers tracking what they've already read"
Focus ring — link outline: 3px solid var(--arxiv-focus-ring) / offset 2px DESIGN-POLICIES.md: "Use :focus-visible (not :focus). All interactive elements must have a visible focus ring."
Focus ring — list region Same ring, outline-offset: -3px (inside card border) DESIGN-POLICIES.md: "Every scrollable region is keyboard-reachable (tabindex='0')."
Off-site signal Destination name (text) + arrow-up-right icon (geometric) + sr-only "(opens in new tab)" (AT) + target="_blank" DESIGN-POLICIES.md: "Never use color as the sole means of conveying information (WCAG 1.4.1). Always provide a secondary cue."
Overflow threshold 6 rows; 7+ scrolls internally at max-height: 272px (~6.5 rows, half-item peek) DESIGN-POLICIES.md: "Truncation always signals continuation … where a region must scroll internally, size it so the last visible item is visibly cut mid-item."
Accessible name on list aria-label="N research artifacts" — total count always available to AT DESIGN-POLICIES.md: "Every scrollable region … accessible name carrying the total."
Card border-radius 6px — matches the established component shape token DESIGN-POLICIES.md: "Border radius: 6px for all buttons, icon buttons, and segmented controls." Applied consistently to card shapes.
Transition timing background 0.12s — row hover only DESIGN-POLICIES.md: "0.12s for background, border, color." Disabled under prefers-reduced-motion: reduce.
No primary button No Open Blue primary button in this card Product: "reads as browsable supplementary material, not a primary call to action." BRAND.md: "The interface gets out of the way."
Font families Body: --arxiv-font-sans (IBM Plex Sans); labels: --arxiv-font-condensed (IBM Plex Sans Condensed) DESIGN-POLICIES.md: "Use only IBM Plex Sans, IBM Plex Sans Condensed, IBM Plex Mono, and STIX Two Math."
No metrics No download counts, view counts, or popularity signals on artifact rows DESIGN-POLICIES.md: "arXiv does not display view counts, download counts, or citation counts on public pages."

HTML markup

Minimal working example for a two-artifact card. The <section> landmark and aria-labelledby on it, paired with a real <h2>, ensure screen readers surface the card as a named region. The list's aria-label should be computed by the template and updated to the actual count.

<section class="ds-artifact-links"
         aria-labelledby="artifact-heading">
  <h2 class="ds-artifact-links-heading"
      id="artifact-heading">
    Datasets &amp; code
    <!-- optional count badge -->
    <span class="ds-artifact-links-count">2 artifacts</span>
  </h2>

  <!-- tabindex="0" → keyboard users can Tab here and scroll.
       aria-label carries the total so AT users know the full
       count even when the list is clipped by max-height.
       role="list" preserves list semantics on styled lists
       in Safari/VoiceOver. -->
  <ul class="ds-artifact-links-list" role="list"
      tabindex="0" aria-label="2 research artifacts">

    <li class="ds-artifact-links-row">
      <span class="ds-artifact-label">Training data</span>
      <span class="ds-artifact-dest">Zenodo</span>
      <a class="ds-artifact-link"
         href="https://zenodo.org/record/123456"
         target="_blank" rel="noopener noreferrer">
        zenodo.org/record/123456
        <!-- sr-only text + icon = two non-color off-site cues -->
        <span class="is-sr-only"> (opens in new tab)</span>
        <svg class="ds-artifact-ext-icon" aria-hidden="true"
             viewBox="0 0 12 12" width="12" height="12"
             stroke="currentColor" fill="none" stroke-width="1.75"
             stroke-linecap="round" stroke-linejoin="round">
          <path d="M2 10L10 2M5 2h5v5"/>
        </svg>
      </a>
    </li>

    <li class="ds-artifact-links-row">
      <span class="ds-artifact-label">Source code</span>
      <span class="ds-artifact-dest">GitHub</span>
      <a class="ds-artifact-link"
         href="https://github.com/example/paper-repo"
         target="_blank" rel="noopener noreferrer">
        github.com/example/paper-repo
        <span class="is-sr-only"> (opens in new tab)</span>
        <svg class="ds-artifact-ext-icon" aria-hidden="true"
             viewBox="0 0 12 12" width="12" height="12"
             stroke="currentColor" fill="none" stroke-width="1.75"
             stroke-linecap="round" stroke-linejoin="round">
          <path d="M2 10L10 2M5 2h5v5"/>
        </svg>
      </a>
    </li>

  </ul>
</section>
Heading level: The example above uses <h2>. The consuming template should use whatever level fits the page's heading outline — .ds-artifact-links-heading provides the visual treatment regardless of the tag.
Count in aria-label: The list's aria-label must be computed by the server template (e.g., Jinja {{ count }} research artifacts) — not hardcoded. It should always reflect the actual number, including when new artifacts are added.
No JS required: The card is fully functional before any JavaScript runs — links navigate, keyboard works, scrollable region is reachable via Tab. Any future JS enhancement (e.g., client-side sorting) layers on top and degrades gracefully if disabled.
