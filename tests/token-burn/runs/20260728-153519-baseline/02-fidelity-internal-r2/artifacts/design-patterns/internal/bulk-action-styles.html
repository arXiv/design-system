arXiv Bulk Action Bar — Component Reference

A contextual toolbar for the arXiv Check moderation queue. Sits directly above the queue table and visually unifies with it; appears populated when one or more rows are checked. Offers three actions on the selection — Approve (primary), Put on hold (neutral), Remove (destructive with inline confirmation). This page shows all five bar states.

Idle — Nothing Selected

The bar occupies its slot above the table at all times so the table does not shift when a selection is made. A muted hint tells moderators what to do; checkboxes are available but the "select all" control is disabled until a selection exists.

Button hierarchy: Approve selected → btn-primary (Access Lime — the common, safe action and the internal-tools primary); Put on hold → btn-secondary (lime-tint, neutral); Remove selected → btn-destructive (Danger Red — irreversible). One primary button per action group; the others provide explicit but lower-emphasis paths.

Bar background + border: --sec-bg (#f0f9e8 — the secondary button lime tint) and a 2 px --lime bottom border. Both tokens already exist in design-system.css; no new values introduced. The lime matches the primary button fill so the "armed" bar reads as a family with the action it promotes.

Selected row tint: .is-selected td uses var(--sec-bg) — the same lime tint as the active bar — so selected rows and the bar read as one visual group.

"Clear selection" affordance: Uses btn-link (Library Grey underline) rather than btn-tertiary. Per the button system: use a link-style button for low-emphasis inline actions that sit alongside text. A boxed tertiary button here would over-weight the affordance and compete with the action buttons.

Confirm Destructive Action

Clicking "Remove selected" does not fire immediately. The action buttons are replaced inline with a plain-language confirmation prompt. The bar retains the selection count and Clear link so the moderator knows what is about to happen. Checkboxes are disabled during this state to prevent accidental selection changes while the confirm prompt is open.

Destructive buttons must always be paired with a confirmation step

"Remove selected" must never fire on first click. Clicking the button replaces the action area with an inline "Remove N submissions permanently? [Confirm remove] [Cancel]" prompt — the confirmation step required by DESIGN-POLICIES.md for all destructive actions. The 2 px --danger bottom border signals the pending irreversible state. Pressing Escape or "Cancel" returns the bar to the active selection state.

Copy: "Remove 3 submissions permanently?" — states what will happen (remove), how many (3), and the consequence (permanently). Matches the arXiv brand voice: honest, plainspoken, no softening. "Confirm remove" mirrors the original button label so moderators are never guessing what they are confirming.

Action Succeeded

After an action completes, the bar's content is replaced with a success message using role="status" (polite — announced by screen readers at the next natural pause). The 3 approved submissions have left the queue; the table now shows only the 2 unaffected rows. A dismiss button returns the bar to idle.

ARIA: role="status" maps to aria-live="polite" — the outcome is read at the next natural pause without interrupting the user. Use role="alert" only for error states (see below).

Focus management (production): On entering the success state, move focus to the bar message element (add tabindex="-1" and call .focus()). On dismiss, return focus to the bar's idle hint or the first table row so keyboard users are never stranded.

Copy: "3 submissions approved." — count, action, period. Plain past tense. No "Success!", no exclamation marks, no marketing tone. Honest and plainspoken per arXiv brand voice.

Action Failed

When an action fails, the bar shows an error message with role="alert" (assertive — announced immediately). The selection is preserved so the moderator can retry without re-selecting. This is especially important for the Remove flow: a moderator should not have to re-select a group they already confirmed.

ARIA: role="alert" is assertive — announced immediately, interrupting the current screen-reader utterance. Reserve it for genuine errors; do not use it for success states or informational messages.

Copy: "Action failed. Your selection is preserved — try again or contact support." Three pieces of information: what happened (failed), what's still good (selection preserved), what to do next (retry or contact). Plain language, no jargon.

Dismiss behaviour: Dismissing the error returns the bar to the active (selection) state — not idle — because the selection survived. The moderator picks up where they left off.

Implementation Notes

Visual connection — .queue-block: Wrap the bar and table in a container with border: 1px solid #ddd8d2; border-radius: 6px; overflow: hidden. Override the table's own border and radius inside: .queue-block .ds-table { border: none; border-radius: 0; }. This makes bar and table one visually unified block — no gap, no double-border seam at the join.

Tokens — no new values introduced: --sec-bg (active bar + row tint) · --sec-bg-hover (selected row hover) · --sec-border (checkbox accent-color) · --lime (active bar bottom border) · --danger (confirm-state border + confirm-text color) · --success-bg/border/fg · --error-bg/border/fg · --focus-ring · --text · --grey · --space-2. All from design-system.css :root.

Reduced motion: The transition on .bulk-bar (background and border-color) is disabled under prefers-reduced-motion: reduce. State changes still happen; only the animated transition is suppressed.

Select-all / indeterminate: Set checkboxEl.indeterminate = true in JavaScript when a partial selection exists — the HTML aria-checked="mixed" attribute conveys the state to screen readers but does not render the visual indeterminate indicator. Both are required.

z-index: This component is not positioned and requires no z-index. The bar flows in document order above the table. Only toasts, sticky headers, and modals use z-index in this system — the bulk bar is neither.
