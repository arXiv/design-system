Submission Type Badges

Color-coded labels that identify a submission's type in the moderation queue and Admin Console. Four types are established: New, Replacement, Withdrawal, and Cross-list. All are rendered from .type-badge + a type modifier defined in design-system.css.

This page is locked to light mode — the badge component has no dark-mode token overrides yet. See dark-mode-decision.md.

Variants

Each badge uses a background fill, a 1px border, and a text color. All four pass WCAG AA (4.5:1) text contrast; three of four reach AAA (7:1).

At scale — larger font context

New Rep Wdr Cross

Badges scale with their container's font-size because padding is set in em-equivalent fixed values — they stay compact regardless of surrounding text size.

Semantic meanings: .type-new — first submission of a paper. .type-rep — replacement (updated version, e.g. v2, v3). .type-wdr — withdrawal requested by the submitter. .type-cross — cross-listing to an additional subject category.
Do not invent new types. These four match arXiv's submission taxonomy exactly. If a new submission type is introduced in the system, add it to design-system.css and update this page — do not create one-off badge colors locally.

In a moderation queue

The primary context for type badges is the Type column of a .ds-table. The column header provides the accessible label; the badge text reinforces it. The monospace type stack aligns badges with arXiv IDs in adjacent columns.

In a table: The "Type" column header gives the badge its accessible context. Screen readers announce the cell value — e.g. "New" — with the column header as label. No additional aria-label is needed when a column header is present.
Sort order convention: When sorting by type, the established order is New → Rep → Cross → Wdr (mirroring the arXiv Check implementation). Apply this order to data-type attributes or server-side sort keys.

Inline with metadata

Badges can lead a metadata line in a submission detail view or a compact summary row. Use align-items: baseline on the flex container to keep the badge optically grounded with surrounding text.

  • Cross 2506.18294 — cross-listing from math.AP to cs.NA
  • Wdr 2504.07650 — withdrawal requested by submitter on 2026-07-25
Inline accessibility: When a badge appears without a surrounding table or explicit column header, add aria-label with the full word to disambiguate the abbreviation — e.g. aria-label="Replacement" on .type-rep, aria-label="Withdrawal" on .type-wdr. In a table with a "Type" column header, aria-label may be omitted.

Colors and contrast

Colors are read from the live stylesheet at runtime via getComputedStyle, so this table cannot drift from design-system.css. Contrast ratios are text-on-background, WCAG formula.

Variant Meaning Background Border Text Contrast
Color is never the sole signal (WCAG 1.4.1). Each badge's text label — "New", "Rep", "Wdr", "Cross" — identifies the submission type independently of its color. The meaning survives grayscale rendering, forced-colors OS mode, and high-contrast themes.
Color palette derivation. .type-new uses a light blue tinted from the info/navy family (connects to the .seg-neutral active state). .type-rep uses the existing version-warning amber tint (--warning-bg family). .type-wdr uses a dark warm-grey from the Repository Brown ladder — neutral, terminal. .type-cross uses a warm light-grey, the lowest-emphasis badge to reflect that cross-listing requires the least moderation attention.
Dark mode is not defined yet. The badge colors are hardcoded hex values, not CSS custom properties, because dark-mode execution is explicitly deferred for internal components. When the dark-mode tokenization pass lands (Phase 2, see DESIGN-PROGRESS.md), these values should be promoted to tokens and a dark override block added to the @media (prefers-color-scheme: dark) section of design-system.css.

Usage

Apply .type-badge plus exactly one type modifier to a <span>. The base class handles shape and typography; the modifier supplies the color. Place inside a semantic container — a table cell, list item, or labelled region.

<!-- In a table cell (column header provides the label) -->
<td><span class="type-badge type-new">New</span></td>
<td><span class="type-badge type-rep">Rep</span></td>
<td><span class="type-badge type-wdr">Wdr</span></td>
<td><span class="type-badge type-cross">Cross</span></td>

<!-- Inline, outside a table — add aria-label for the full word -->
<span class="type-badge type-rep" aria-label="Replacement">Rep</span>
<span class="type-badge type-wdr" aria-label="Withdrawal">Wdr</span>
Typography. Badges render in IBM Plex Mono (with SF Mono / Fira Code / system monospace fallbacks). The monospace stack is intentional — type codes appear alongside arXiv IDs in most queue contexts, and the shared font signals "system metadata" rather than editorial text. Do not override the font family on individual badges.
Size and shape. The base class sets font-size: 11px, padding: 1px 6px, and border-radius: 3px. These values are fixed — do not scale badges up for emphasis or down for compactness. If a wider target area is needed (e.g. on touch-primary surfaces), wrap the badge in a larger cell rather than enlarging it.
