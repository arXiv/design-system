Bulk-Action Bar — Component Reference

A contextual action strip for the arXiv Check moderation queue. Appears above the table when one or more submissions are selected; offers approve, hold, and remove actions. Visually fused to the queue table via shared border edges.

States

Four states: bar absent (nothing selected), bar active (selection made), destructive confirm (after clicking Remove), and feedback (success or failure after an action completes). Each is shown above a stub queue table to illustrate the visual connection.

Usage Notes

Remove selected always requires a two-step confirm

Firing removal on a single click is a design-system violation. The confirm sub-state is mandatory per the destructive-button policy. The confirm message must include the count ("Remove 3 submissions? This cannot be undone.").

Button hierarchy is fixed: Approve → Hold → Remove

Approve selected is the common, safe action: .btn-primary (lime). Put on hold is neutral: .btn-secondary. Remove selected is destructive: .btn-destructive. Never swap these colors — the hierarchy is semantic, not decorative.

Visual connection to the table: .bulk-bar uses border: 1px solid #ddd8d2; border-bottom: none; border-radius: 6px 6px 0 0 — the same border color as .ds-table. The table inside .bulk-bar-wrap then gets border-top: none; border-radius: 0 0 6px 6px via the page-local .bulk-bar-wrap .ds-table rule. These are glue styles scoped to this page; they do not modify the shared .ds-table component.

Selected row highlight: Checked rows use background: #f0f9e8 (--sec-bg, the lime tint). This visually ties the affected rows to the lime action bar and makes the selection set scannable at a glance. The tint is subtle enough not to interfere with the table's hover state.

ARIA and screen readers: The count element uses role="status" (polite live region) so selection changes announce without interrupting. The error bar uses role="alert" (assertive). The success bar uses role="status". A separate aria-live="assertive" region announces the confirm step. On confirm open, focus moves to the "Confirm removal" button. On cancel or dismiss, focus returns to the Remove button or the first unchecked row checkbox respectively.

Dismiss / clear: Dismissing a feedback bar restores the queue to idle. "Clear selection" unchecks all rows and hides the bar. Both use .btn-link — they are incidental affordances, not primary actions, so they do not warrant button-weight chrome.

CSS promotion: Once this pattern stabilises, .bulk-bar, .bulk-bar-wrap, .bulk-bar-lhs, .bulk-bar-rhs, .bulk-bar--confirm, .bulk-bar--success, and .bulk-bar--error should be extracted into design-system.css and prefixed with .ds-. The .bulk-bar-wrap .ds-table modifier stays in the consuming page — it is a layout seam, not a component style.
