Segmented Control

An exclusive-choice button group (like a radio group, but rendered as adjacent buttons). Used for inline decisions where all options should be visible at once. Three semantic color variants for the active state: positive (green), neutral (blue), and negative (red).

Markup: Use a <fieldset class="seg-control"> with a <legend class="sr-only"> for accessibility. Each option is a <button class="seg-btn"> with a semantic modifier: .seg-positive, .seg-neutral, or .seg-negative. Toggle .active on click.
Semantic colors:
  • Positive (.seg-positive) — green. Accept, approve, confirm.
  • Neutral (.seg-neutral) — blue. Informational or secondary choice.
  • Negative (.seg-negative) — red. Reject, deny, remove.
When to use: Best for 2–4 mutually exclusive options where all choices should be visible (no dropdown). For more than 4 options, use a <select> or radio group instead.

Toggle Switch

A boolean on/off control for settings and feature flags. Wraps a visually-hidden checkbox with a custom track and sliding thumb. Off state is warm grey; on state uses the brand lime-green.

States

Off
On

Interactive — with labels

Markup: Wrap everything in a <label class="toggle-switch">. The hidden <input type="checkbox"> provides native form semantics and keyboard support. The .toggle-track and .toggle-thumb handle the visual rendering. The optional .toggle-label provides an uppercase condensed text label.
Colors:
  • Off — track #ddd8d2 (warm grey), label #b0aba6 (muted)
  • On — track #9cb522 (brand secondary border), label #4a5a0a (dark green)
Accessibility: The hidden checkbox is keyboard-focusable; the :focus-visible rule shows a focus ring around the track only on keyboard navigation, not on mouse click. The <label> wrapper means clicking anywhere (track, thumb, or label text) toggles the state.

Required indicator: Place <span class="field-required">*</span> inside the <label>. The asterisk renders in var(--danger) red. Always pair with required and aria-required="true" on the field.
Invalid state: Add .is-invalid to the input/textarea/select. This applies a red border and a subtle red focus ring. Use JavaScript to toggle the class on validation failure and clear it when the user corrects the input.
Error message: Use <p class="field-error" hidden> below the field. Remove [hidden] to show it. Link it to the field with aria-describedby so screen readers announce the error.
Validation flow:
  • Validate on submit (not on first keystroke — avoid premature errors).
  • Once invalid, re-validate on each input event so the error clears immediately when corrected.
  • On failure, focus the first invalid field.
