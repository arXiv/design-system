Public-side button styles

Primary and secondary buttons for arxiv.org public pages. Reference for design-patterns/public/design-system.css.

Construction

Both variants share dimensions, shape, and depth language. Only the fill and border colors differ.

  • 1.5px transparent border + dual-background linear-gradient(...) padding-box, linear-gradient(...) border-box for a gradient border that follows border-radius.
  • Border gradient: lighter top → darker bottom, in solid hex colors so the hue is unambiguous regardless of what's behind the button.
  • Inner vignette via box-shadow: inset 0 0 6px softly darkens the perimeter equally on all sides. The center of the button stays the canonical fill color.
  • Hover brightens: primary fill lightens; secondary fill stays white but the inner vignette nearly vanishes so the surface reads as more luminous. Border deepens slightly for feedback; outer drop unchanged.
  • Pressed: 1px drop via translateY, outer drop removed, vignette deepened, border flattened to a single mid-tone.

Secondary on tinted surface (.on-tint)

When a secondary button sits inside a tinted section (e.g., the HTML reader's light-blue footer band), the default white fill creates too much contrast with the surface and the button reads as "primary." The .on-tint modifier swaps the fill to Card Grey — same luminance, warm hue — so the button reads as intentionally secondary via warm-on-cool material differentiation. Hover brightens to Warm Wash, staying in the warm family.

Usage

Apply .ds-btn as the base class, then one variant.

<!-- Primary -->
<a href="/html/2604.22725v1" class="ds-btn ds-btn-primary">HTML</a>

<!-- Secondary -->
<a href="/src/2604.22725v1" class="ds-btn ds-btn-secondary">TeX Source</a>

Use the primary for the page's call-to-action (HTML, PDF on the abstract page). Secondary is for adjacent destinations of equal weight but lower priority (TeX Source). Don't mix this primary with the internal Access-Lime primary on the same page — they signal different contexts.

Accessibility notes

  • Contrast. Black text (--ink) on #a5d6fe passes WCAG AA for normal text. Library Grey text (--grey) on white passes 5.83:1. Border colors at the bottom of each gradient pass the 3:1 UI-component minimum against their respective surfaces.
  • Focus ring. outline: 3px solid var(--arxiv-link-blue) with 2px offset. Uses :focus-visible, not :focus, so the ring only shows on keyboard nav (DESIGN-POLICIES.md).
  • Color alone. Hover state changes the fill AND the border AND the inner vignette — not just one. Press state changes position AND shadow. Meets WCAG 1.4.1 (color not the sole means).
  • Target size. Default padding produces ~37×~85 px buttons; comfortably above WCAG 2.5.8's 24×24 minimum.
  • Reduced motion. The only motion is the 1px pressed-state translateY. If a stronger motion-reduction guarantee is needed, wrap the transition in @media (prefers-reduced-motion: no-preference).
