Artifact links card

The .ds-artifact-card component — lists a paper's external research artifacts (datasets, code repositories, supplementary material) on the abstract page. Each row shows an artifact type label, the hosting platform, and a direct off-site link.

The card reads as browsable supplementary material, not a primary call to action. It sits alongside abstract metadata. All links navigate off-site; three independent cues signal this to every user (icon, sr-only text, target="_blank").

Single artifact

The minimum state — one row. No overflow handling; no disclosure button. The card shows any number of rows from 1 to 5 exactly as authored.

Overflow — collapsed (6 or more artifacts)

When a paper has 6 or more artifacts, JavaScript hides rows 6+ and injects a .ds-artifact-show-all button. The button label states the total count so the reader knows what is hidden before expanding. Without JavaScript all rows remain visible — scripts must not carry content.

Interaction states

Row-level hover and keyboard focus states. The entire row is the interactive target — a block link (<a> with display: grid) so mouse users click anywhere. Tab stops at each anchor; focus rings are inset so they stay within the card.

In-context placement

The card is intended for the abstract page's secondary sidebar or metadata column, placed below the primary actions (PDF, HTML). It does not use primary button chrome or Open Blue fills — it reads as a directory of supplementary links, not a feature.

Design notes

Overflow threshold: 5 rows. With 6 or more artifacts, JavaScript hides rows 6+ and injects a .ds-artifact-show-all disclosure button. The button label always states the full count ("Show all 12 links"). Threshold chosen to keep the card compact for the majority of papers (≤5 artifacts) without cutting off early.
Progressive enhancement. All rows are present and visible in the server- rendered HTML. JavaScript optionally collapses overflow rows. Without JS (or on failure), the complete list remains accessible — scripts never carry content (DESIGN-POLICIES.md, "Chrome and interaction structure").
Off-site signal. Three independent cues — a visible ↗ icon (aria-hidden), screen-reader text "(opens in new tab)" via .is-sr-only, and target="_blank" rel="noopener noreferrer" — so the "navigates off-site" meaning survives forced-colors, AT use, and icon-only scenarios. Color alone is never the sole signal (WCAG 1.4.1).
Block link pattern. The entire row is a single <a> element with display: grid. This gives mouse users a large click target, while screen readers hear one clear link label (type + platform + URL + "(opens in new tab)") per row. The link text is descriptive without the surrounding context.
Not a primary action. The card uses no Open Blue fills, no primary-button chrome, and no emphasis-first heading. Open Blue is locked to PDF/HTML primary actions (DESIGN-POLICIES.md, "Internal vs. Public pages"). Artifact links are secondary reference material: browsable, not promoted.

CSS class reference

Class Element Purpose
.ds-artifact-card <section> Card shell — white bg, hairline border, 6px radius, overflow:hidden
.ds-artifact-card-heading <h2> 11px condensed-caps heading ("DATASETS & CODE") in Library Grey
.ds-artifact-list <ul> Unstyled list wrapper
.ds-artifact-row <li> Row — carries the hairline bottom border; last-child border removed
.ds-artifact-row-link <a> Block link covering the full row; 3-column grid; hover + :focus-visible states
.ds-artifact-type <span> Artifact category label — 14px, weight 500, Repository Brown
.ds-artifact-platform <span> Hosting platform name — 13px, Library Grey
.ds-artifact-url-cell <span> Link text + icon wrapper — Link Blue, underlined, ellipsis on overflow
.ds-artifact-ext-icon <svg> 12×12 stroke ↗ icon; aria-hidden="true"; sibling .is-sr-only carries the meaning
.ds-artifact-show-all <button> Disclosure button injected by JS (hidden by default); reveals rows 6+

Copy pattern

Minimal markup for one row. Repeat the <li> block for each artifact. The .ds-artifact-show-all button is injected and managed by JS when the list has more than 5 rows — it is not included in the static HTML template. 

<section class="ds-artifact-card" aria-labelledby="artifacts-heading">
  <h2 class="ds-artifact-card-heading" id="artifacts-heading">
    Datasets &amp; code
  </h2>
  <ul class="ds-artifact-list" role="list">

    <li class="ds-artifact-row">
      <a class="ds-artifact-row-link"
         href="https://zenodo.org/record/8231451"
         target="_blank" rel="noopener noreferrer">
        <span class="ds-artifact-type">Training data</span>
        <span class="ds-artifact-platform">Zenodo</span>
        <span class="ds-artifact-url-cell">
          zenodo.org/record/8231451
          <svg class="ds-artifact-ext-icon" viewBox="0 0 24 24" fill="none"
               stroke="currentColor" stroke-width="2"
               stroke-linecap="round" stroke-linejoin="round"
               aria-hidden="true">
            <path d="M7 17L17 7"/><path d="M7 7h10v10"/>
          </svg>
          <span class="is-sr-only">(opens in new tab)</span>
        </span>
      </a>
    </li>

    <!-- repeat <li> for each artifact … -->

  </ul>
  <!-- .ds-artifact-show-all button injected by JS when total > 5 -->
</section>

JS contract for overflow: when the list has more than 5 rows, the consuming page script should: (1) set the hidden attribute on rows 6+; (2) append a .ds-artifact-show-all button with aria-expanded="false" and aria-controls pointing to the list; (3) on button click, remove hidden from all rows, set aria-expanded="true", and optionally hide the button. No JS = all rows visible.
