Artifact Links Card

The .ds-artifact-links card lists a paper's external research artifacts (datasets, code repositories, supplementary material) on the public abstract page. Each row links off-site and shows an artifact label, the destination platform, and an off-site arrow. The card reads as browsable supplementary material — not a primary call to action.

Row states

Each artifact row is a full-width <a>. Default is Repository Brown text at rest. Hover fills the row with Active Wash (--arxiv-active-bg) and deepens the off-site arrow. Keyboard focus shows a 3 px inset ring. Visited state is suppressed — these are navigational links, not inline body text.

Multiple artifacts — at threshold (8 rows)

Up to 8 artifact rows display without any overflow handling. Eight rows is the threshold: a card of this height sits comfortably alongside the abstract-page sidebar without dominating. At 9 or more, use .ds-artifact-links-more (see the next section).

Usage

Minimal single-artifact example, then the overflow pattern.

Overflow rule. Show the first 8 artifacts in .ds-artifact-links-list without any disclosure. At 9 or more artifacts, split the list: first 8 in the main <ul>, remainder in a <details class="ds-artifact-links-more">. The <summary> carries the count ("4 more artifacts") — an explicit count per DESIGN-POLICIES.md's truncation preference. The + /− glyph signals the open/closed state; no JavaScript required. The consumer is responsible for filling in the count.

External links. Every .ds-artifact-links-row must include target="_blank", rel="noopener noreferrer", and a per-row <span class="is-sr-only">(opens in new tab)</span>. The off-site arrow SVG carries aria-hidden="true" — the sr-only text is the AT signal; the icon is purely visual.

ARIA. Wrap the card in <section aria-labelledby="[id]"> and point the id at the .ds-artifact-links-title. This creates a complementary landmark that screen readers can navigate to directly, and announces "Data and code" (or whatever heading the consumer supplies) before reading the list.

Heading level. .ds-artifact-links-title only sets visual style — pick the heading level that fits the page outline (usually h2 or h3 on the abstract page, depending on the sidebar's heading hierarchy).

Placement. The card belongs in the sidebar rail alongside other browsable metadata accordions (version history, paper information). It is not a main-column component — the rail is opt-in, the main column is what every reader must meet (see organizing-content.html).

Minimal example:

<section class="ds-artifact-links" aria-labelledby="al-h">
  <h2 class="ds-artifact-links-title" id="al-h">Data &amp; code</h2>
  <ul class="ds-artifact-links-list">
    <li>
      <a class="ds-artifact-links-row"
         href="https://zenodo.org/record/1234567"
         target="_blank" rel="noopener noreferrer">
        <span class="ds-artifact-links-label">Training data</span>
        <span class="ds-artifact-links-dest">Zenodo</span>
        <svg class="ds-artifact-links-ext" aria-hidden="true"
             viewBox="0 0 12 12" fill="none"
             stroke="currentColor" stroke-width="1.75"
             stroke-linecap="round" stroke-linejoin="round">
          <path d="M2 10L10 2M5 2H10V7"/>
        </svg>
        <span class="is-sr-only">(opens in new tab)</span>
      </a>
    </li>
  </ul>
</section>

Overflow pattern (9+ artifacts):

<section class="ds-artifact-links" aria-labelledby="al-h">

No metrics on public pages

DESIGN-POLICIES.md prohibits display counts on public pages. Do not add download counts, citation counts, or view counts to artifact rows — even as a secondary label.
