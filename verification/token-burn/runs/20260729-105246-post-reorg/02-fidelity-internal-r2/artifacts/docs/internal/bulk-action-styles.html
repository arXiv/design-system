Bulk Action Bar

Context-sensitive toolbar for the arXiv Check moderation queue. Appears directly above the queue table when one or more submissions are selected, offering Approve, Hold, and Remove actions on the selection.

Reuses .btn-primary, .btn-secondary, .btn-destructive, .btn-link, and .ds-alert from design-system.css. Page-specific layout glue lives in this page's own style block.

Idle — nothing selected

The bar is always rendered above the table. When no rows are checked, all three action buttons carry the disabled attribute — they don't disappear (design-system rule: actions disable, never vanish). The idle background matches the table header tone so the unit reads as connected chrome at rest.

Selection active

When at least one row is checked: the count updates, the "Clear selection" affordance appears, and all three action buttons become enabled. The bar background shifts to the lime-tint surface (--sec-bg) to signal that the selection context is live. Checked rows receive a matching lime-tint row highlight. Clicking Remove selected must open a confirmation <dialog> before acting.

Success

After an action completes the action buttons are replaced by a .ds-alert-success spanning the full bar width. The count of affected submissions appears in the message. role="status" triggers a polite screen-reader announcement without interrupting the current focus.

Failure

If the action fails the bar shows a .ds-alert-error with an error summary and a recovery path. role="alert" fires an assertive announcement so the moderator is immediately informed. Dismissing the error returns the bar to the selection-active state (state 2) with the selection intact, so they can retry without re-selecting.

Design rules applied

Internal surface — Access Lime primary. Approve selected uses .btn-primary (lime background) because this is an internal staff tool. Open Blue is the public-page primary; the two must never be crossed — the color difference tells moderators which surface they are on.
Actions disable, they don't disappear. The three action buttons are always rendered. They receive the disabled attribute when no rows are selected, and are re-enabled as soon as any row is checked.
Destructive action — always confirm. .btn-destructive is reserved for hard-delete and irreversible actions and must always pair with a confirmation step. Here that step is a native <dialog>; the button carries aria-haspopup="dialog" so assistive technology knows a dialog follows.
Color alone is never the sole signal (WCAG 1.4.1). Each alert state pairs a distinct SVG icon shape with a leading word. The lime-tint bar background in the active state is a secondary cue; the count text is the primary signal.
Spacing from the scale. All padding and gap values use --space-3 (12 px) and --space-4 (16 px) from the 4-px-based scale. No off-scale values are introduced.
No z-index, no sticky chrome. The bar is static document flow. Sticky chrome requires explicit approval per the design policies; the bar does not qualify.
Self-hosted only — no external URLs. Icons are inline SVG paths (Lucide geometry); no CDN, no Bootstrap Icons link, no Google Fonts import.
ARIA roles on alerts. Success uses role="status" (polite announcement); failure uses role="alert" (assertive). Both carry aria-hidden="true" on their icon SVGs.
