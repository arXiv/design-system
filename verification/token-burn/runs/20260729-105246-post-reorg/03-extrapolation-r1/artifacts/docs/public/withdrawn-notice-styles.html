Withdrawn-paper notice

New pattern for author-initiated withdrawal: a persistent advisory banner placed in the main reading column, below the date row and above the authors, so every reader encounters it before engaging with the abstract. The scholarly record (abstract, all versions) remains permanently online and downloadable.

No prior pattern covers this case. The decisions below are derived from alerts.html, version-display.html, BRAND.md, and DESIGN-POLICIES.md; each entry names its source per the AGENTS.md routing rule for new patterns.

Design rationale

Seven decisions, each traced to a specific rule in the design system. This is a derived pattern (no prior spec), so the reasoning is shown in full.

Decision 1 — Warning variant, not error or info

Source: docs/alerts.html — "Don't escalate: an old paper version is a warning, not an error." Withdrawal is more significant than an old version, but nothing failed — the paper record is intact, downloads work, authors acted intentionally. Warning (amber) signals "worth knowing, nothing broke," which precisely describes withdrawal. Error is reserved for system failures; info is too calm for a status change a cited reader may have no idea about.

Decision 2 — Below the date row, above the authors

Source: docs/alerts.html placement rule — "Time-critical messages live in the main reading column where every reader meets them — don't tuck a warning into a rail the reader may never open." The older-version warning in mockups/abstract-redesign.html occupies this exact slot; withdrawal mirrors it. When both are present (reader on an older version of a withdrawn paper), the withdrawal notice goes first — it is the more fundamental status, rendering the "newer version" link moot.

Decision 3 — No dismiss button

Source: docs/alerts.html — "If a message must persist or is about the current paper, it's an alert." Withdrawal is a permanent property of this paper, not a time-bound site announcement. The dismissable variant (.ds-alert-dismiss) is for transient feedback; this notice must show every visit. The site banner's dismiss policy (DESIGN-POLICIES.md, Banner) does not apply here.

Decision 4 — Author's reason is shown verbatim

Source: docs/BRAND.md (Voice: Honest) — "We say what's true, including the unflattering parts. No marketing gloss, no overclaiming." arXiv does not editorialize about an author's decision to withdraw; the reason text is shown as the author wrote it. The notice does not soften, reframe, or summarize the reason — readers and citers deserve the exact language. When no reason is given, the body says so directly ("No reason was provided.").

Decision 5 — Plain title, no alarm language

Source: docs/alerts.html writing guidance — "Match arXiv's voice: plain, direct, no exclamation marks, no blame." The title is "Withdrawn by the authors" — factual, not alarmist. No "WARNING:" prefix, no "RETRACTED" in all-caps, no implied misconduct. Most withdrawals are honest self-corrections. Source: docs/BRAND.md (Voice: Accessible) — "Nobody should feel they need a secret handshake to use arXiv." A highly-cited withdrawn paper is still scholarly record; the notice respects that.

Decision 6 — Download actions remain fully enabled

Source: AGENTS.md — "Actions disable, they don't disappear." The paper content is still downloadable; there is no action to disable. The HTML, PDF, and TeX Source buttons render in their normal active state. A quiet label below the action column ("Downloading withdrawn version") provides context without visually demoting the buttons or implying the content is inaccessible.

Decision 7 — "(withdrawn)" extends the date-row grammar

Source: docs/version-display.html — "Current is bold and aria-current, never color alone." The withdrawn version is still the latest version; it keeps its bold treatment. The word "(withdrawn)" is inserted alongside "(this version)" in the date row as a second non-color signal (WCAG 1.4.1). Derived per AGENTS.md routing for new patterns: "nearest pattern above + BRAND.md — derive from documented rationale; say so in comments." The parenthetical uses the warning foreground token for a color cue that is reinforced by the word itself.

Live examples

Rendered from public/design-system.css. Three scenarios: viewing the withdrawn (latest) version; viewing an older pre-withdrawal version; and a minimal withdrawal with no substantive reason given.

Scenario A — Viewing the withdrawn version

The reader arrived directly at this paper. The notice is the first thing after the date row. Download buttons remain fully active; a quiet label beneath them identifies the content as the withdrawn version.

A geometric proof of the Penrose singularity theorem in modified gravity

Submitted 14 Jan 2024 · , Revised 3 Sep 2024 (this version, withdrawn)   v1 v2 v3

Withdrawn by the authors

Withdrawn 3 Sep 2024. Author’s reason: “An algebraic error in Section 4 invalidates Theorem 2 and consequently the paper’s central claim. The authors intend to submit a corrected version.”

The abstract page and all versions remain available as part of the scholarly record.

L. García, T. Hayashi, R. Müller, S. Okonkwo

We present a purely geometric derivation of the Penrose singularity theorem within the framework of f(R) modified gravity. Working directly with the modified Raychaudhuri equation, we construct a generalized trapped surface condition and demonstrate the existence of incomplete null geodesics without recourse to the Einstein field equations. Scenario B — Viewing an older, non-withdrawn version

The reader arrived via a link that pins to v1. Both the withdrawal notice (fundamental status) and the older-version warning (navigational) appear — withdrawal first, because knowing the paper was later withdrawn is more important than knowing a newer version exists.

Scenario C — Minimal or absent reason

Some withdrawals give a very brief reason or none at all. The notice remains structurally identical; when no reason is provided, the body says so plainly.

Dark matter direct detection via nuclear recoil scattering at the LHC

Rules that travel with this pattern

Always show the notice on every version's page

When a paper's latest version is withdrawn, the notice appears on every version page — not just on v_latest. A reader who arrives at v1 via a citation link must see that the paper was later withdrawn.

Downloads remain active — never disable, never remove

AGENTS.md: "Actions disable, they don't disappear." Downloads work on withdrawn papers. The download buttons are not greyed, not removed, not reordered. A quiet note below the action column identifies which version is being downloaded.

Withdrawal notice before version warning when both appear

Knowing a paper was later withdrawn is more important than knowing a newer version exists. Place withdrawal first; version warning immediately below.

Never use ds-alert-error for withdrawal

Error variant is reserved for system failures (docs/alerts.html). Withdrawal is an author decision, not a failure. Escalating to error would misrepresent the action as a system problem and stigmatize the authors.

Dark mode is inherited, not hand-coded

The --arxiv-warning-* tokens already have dark overrides in design-system.css. This page uses data-theme="light" (AGENTS.md: "New demo pages lock light"), but production pages inherit both light and dark behavior automatically via the tokens.
