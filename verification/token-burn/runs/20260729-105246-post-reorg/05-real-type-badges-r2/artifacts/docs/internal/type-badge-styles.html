Submission Type Badges

Color-coded labels used in the moderation queue and admin tools to identify a submission's type at a glance. Each badge pairs a distinct hue with a short text label so color is never the sole signal (WCAG 1.4.1). Styles are defined in docs/internal/design-system.css.

Badge Palette

Four variants, one per submission type. Apply both .type-badge (base shape and typography) and one type modifier. Do not use one without the other.

All variants — isolated

New .type-badge.type-new New submission — first version of a paper
Rep .type-badge.type-rep Replacement — author-submitted revision
Wdr .type-badge.type-wdr Withdrawal — request to withdraw the paper
Cross .type-badge.type-cross Cross-list — addition to a secondary category
Markup: <span class="type-badge type-new">New</span> — both classes are required. The canonical label text is New, Rep, Wdr, Cross; do not change, abbreviate differently, or translate them.
Color is not the sole signal (WCAG 1.4.1). Each badge carries a text label in addition to its background color. If color is removed (forced-colors mode, greyscale print), the label alone still identifies the type. Never render a badge with an empty label or aria-hidden text.

Moderation Queue Context

Type badges appear in the Type column of a .ds-table queue. A .ds-filter above the table lets moderators narrow to a single type.

Placement: Badges go in a dedicated Type column, kept narrow (60–80 px) so they read as a quick visual scan. Pair the column with a .ds-filter select so moderators can narrow by type; always include All as the default option.
Sort order (Type column): The canonical sort is New (0) → Rep (1) → Cross (2) → Wdr (3), matching the order used in table-styles.html's typeOrder map. Apply this as the default when sorting by the Type column.

Token Reference

Badge colors are component-internal constants defined directly in the .type-* rules in docs/internal/design-system.css. They do not map to :root custom properties and must not be lifted for other uses. The CSS file is authoritative for all values below.

Contrast rationale: The badge text at 11px non-bold does not qualify as "large text" (WCAG requires ≥18px regular or ≥14px bold), so the 4.5:1 AA floor applies. All four variants exceed 4.5:1; three reach AAA (7:1). .type-rep is lowest at 5.6:1 — still AA — chosen so its warm amber reads as visually distinct from the blue (.type-new) and warm-grey (.type-cross) families.
Base class properties (.type-badge): font-family: "IBM Plex Mono", font-size: 11px, font-weight: 400, border-radius: 3px, padding: 1px 6px. Do not override these on individual badge instances — they are part of the component contract.
No dark-mode overrides. The badge palette currently has no dark-mode token overrides. New pattern pages lock to light: <html data-theme="light">. If dark support is added in a future sprint, define overrides in the existing dark-mode block at the bottom of docs/internal/design-system.css.
