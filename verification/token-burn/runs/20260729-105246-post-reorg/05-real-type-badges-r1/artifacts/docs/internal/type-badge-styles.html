Submission Type Badges

Color-coded labels marking submission type in moderation queues and admin tools. Four types: New submission, Replacement, Withdrawal, and Cross-list. Defined in docs/internal/design-system.css under "Submission Type Badges".

All Badge Types

Apply .type-badge (shape and typography) plus one type modifier (color). Both classes are always required. The text label is the primary signal; color reinforces it.

Cross .type-cross Cross Cross-list — paper added to an additional subject category 7.5:1 AAA ✓

Markup pattern: <span class="type-badge type-new">New</span>. Use <span> — badges are not interactive. Do not use <button> or <a>.

In Context: Moderation Queue

Badges appear in the Type column of moderation and admin queue tables alongside other submission metadata. The column header and adjacent cell content together provide full context — color alone is never the only signal.

Type column sizing: Reserve at least 64px for the Type column. "Cross" is the widest label; with its 6px horizontal padding on each side, the badge renders at approximately 50px. Leave room for comfortable scanning in dense queues.

One badge per row: A submission has exactly one type. Never display more than one type badge for the same submission row.

Base Class Anatomy

.type-badge handles all shape and typographic properties. Type modifiers add only background, text color, and border.

Property Value Rationale
display inline-block Sits inline within table cells; does not force a new line
font-family IBM Plex Mono, SF Mono, Fira Code, monospace Monospace signals system/machine-generated classification data
font-size 11px Small enough to stay subordinate to adjacent text; all color pairs clear 4.5:1 at this size
font-weight 400 Regular weight; the monospace face reads clearly without bold
padding 1px 6px Tight vertical padding keeps badge height close to surrounding text; 6px horizontal prevents clipping
border-radius 3px Slightly rounded to distinguish badges from table cell borders, less rounded than buttons (6px) to signal non-interactivity
border 1px solid (color varies) Border provides shape definition against white table cell backgrounds
white-space nowrap Prevents "Cross" or "Wdr" from wrapping in narrow columns

Accessibility

All four badge types meet WCAG 2.1 AA text contrast (4.5:1 minimum for 11px text). Three of four reach AAA.

  • Color is not the sole signal (WCAG 1.4.1). Each badge carries a visible text label — "New", "Rep", "Wdr", "Cross" — so color reinforces meaning but does not carry it alone.
  • Badges are not interactive. Use <span>, not <button> or <a>. No focus styles or interactive ARIA attributes are needed.
  • Screen reader context in tables. When a badge appears in a <td> with a proper <th> column header, screen readers announce both the column name and the badge label (e.g. "Type: New"). No additional aria-label is required in this context.
  • Forced colors (Windows High Contrast mode). In forced-colors mode, the OS replaces all background and foreground colors; the text labels remain readable. Do not set forced-color-adjust: none on badges.
  • Abbreviation legibility. "Wdr" and "Rep" are opaque to new staff. In detail panels or tooltips where space allows, display the full label ("Withdrawal", "Replacement") alongside or instead of the badge. The badge itself uses the short form for visual density in queues.

Dark mode: These pages are locked to light mode (data-theme="light" on <html>). Badge dark-mode color values are not yet defined. When dark mode is enabled for internal tools, add overrides in the @media (prefers-color-scheme: dark) block in design-system.css, following the pattern of other component overrides in that file.

Usage Rules

  • Internal tools only. Type badges are for moderation queues, admin consoles, and other staff-facing surfaces. Do not use them on public-facing arXiv pages.
  • Always use both classes. .type-badge is required alongside the modifier. A modifier class alone produces unstyled text.
  • Do not invent new badge types. The four types map directly to arXiv's submission workflow. If the workflow adds a new submission type, define a new CSS modifier in design-system.css and add it to this page — do not repurpose existing badges for other meanings.
  • One badge per submission row. A submission has exactly one type. Never show more than one type badge for the same row.
  • Placement. In tables, the type badge goes in a dedicated Type column. In detail panels, display it as a labeled metadata field at the same visual weight as other fields.
  • No custom colors. Use only the four defined color combinations. Do not override badge colors with inline styles or one-off CSS rules.
