Bulk Action Bar — arXiv Check

Context bar for the moderation queue. Sits directly above the queue table, sharing its border to form one connected surface. Appears when one or more submissions are checked; offers Approve, Hold, and Remove actions.

Buttons, type badges, table chrome, and status tokens all come from design-system.css. Layout and state-specific surface colors are page-specific glue in this file's <style> block.

Idle — nothing selected

Buttons render disabled, not hidden. Per the interaction rule in AGENTS.md: "contextual actions render disabled when unavailable, not removed." The bar's neutral grey surface matches the table header, signalling it is not yet active.

"Clear selection" uses .btn-link, designed for low-emphasis inline actions ("Clear all", "Reset to default"). Lime-tint bar background comes from var(--sec-bg) — the same token as secondary buttons — so bar and buttons share visual DNA without a new color. Selected row tint (tr.is-selected) uses the same token for continuity between bar and rows.

Confirmation step — Remove selected

Clicking "Remove selected" transforms the bar into an inline confirmation step before executing. Required by the design system: "Always pair [destructive actions] with a confirmation step (dialog or inline confirm)."

Warning surface uses var(--warning-bg / border / fg) — the same palette family as the .ds-alert-warning variant, applied directly to the bar element. The warning-triangle icon is a distinct shape from the success checkmark and error circle, satisfying WCAG 1.4.1 (no color as the sole signal). "Cancel" uses .btn-tertiary — a neutral, low-emphasis button that does not compete visually with the destructive "Confirm removal" action.

Success — action completed

After a bulk action succeeds, the bar slot shows a completion message using var(--success-bg / border / fg). Uses role="status" with aria-live="polite" — polite because the operation has already completed and the announcement is not time-sensitive.

Success surface tokens (--success-bg, --success-border, --success-fg) are shared with .ds-alert-success and the .seg-positive segmented-control variant — one palette family, three contexts. "Dismiss" inherits the surface color via the .is-success .btn-link rule, keeping it legible without a hardcoded value.

Error — action failed

When a bulk action fails the bar shows an error message with Retry and Dismiss affordances. role="alert" with aria-live="assertive" interrupts screen readers immediately — appropriate because the moderator's intended action did not complete and they need to know right away.
