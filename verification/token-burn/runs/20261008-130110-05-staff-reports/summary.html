Read

ALL SECTIONS: - logo in header is correct, that is good. - header includes dark mode toggle, excellent. - page zones are being used, which we decided is not appropriate for dense pages like admin tools, so that is incorrect. - use of cards to organize the sections is good. - staff reports is already in the header nav, then is duplicated lower down on the page. It also duplicates the same words in the heading and in the link below it, which is wasteful. - The cards look a little too plain and could use a redesign pass. Perhaps a variant with a top border in the primary or accent color, for when cards are the prominent content. ACTIVITY CHARTS: - I approve of the use of the secondary nav and the compact filter bar just below the header. - I think the main heading of the page should reflect which subnav the user selected, as well as the filters. So instead of just "computer science" the heading might be "Submissions and holds, All CS" or, with other filters and nan selection it might read "Moderators, cs.DC". This way the heading reflects the user choices and follows their order. - The sort bar is somewhat confusing to me as a user. It has two filter bars and then an apply button, but that is not the expected behavior of sort options. The live site uses a simple button bar and each button toggles that sort immediately. RECENT SUBMISSIONS: - The organization on this page looks pretty good. - I appreciate the more compact date selector. It could be even more compact though, because it is allowing the date picker fields to use up all available width when they do not need that much. it looks odd and I think goes against the design guidelines for form field widths. - The live site includes the option for the user to select to "use these dates for all tabs". This comment applies to all of the options. - When it comes to the pagination at the top and bottom of the table, I think we need a rule that we only need it in both locations when the table goes beyond X number of rows (maybe 25?). When table rows are less than that we only need pagination at the bottom of the table. - The placeholder content that says "Figures: five totals for 16 Sep to 6 Oct 2026" is confusing because it switches to not using a dashed outline and has no top margin. STAFF REPORTS: - this page also uses page zones, which is not appropriate for these admin tools. Even though this page is lighter I think that the same look and feel should be maintained across all of the pages. It does not look right to insert page zones on just a few pages.

Shamsi: notes after seeing them together

I would like to see agents do a review pass of any layout and think carefully about what the primary content is and wether it can be displayed higher on the page. This would mean evaluating all the content for hierarchy again, and also evaluating which DS elements and affordances where used, and if the best choices were made in both cases. What are your thoughts?

What the builds had in common

  • All four: .ds-card--link on both doorway pages, .ds-subnav with a compact filter bar, .ds-subnav--in-page for the views, placeholders, the standard header. None used the light header.
  • Three of four wrote their own placeholder style; each looked different.
  • None reviewed the page for what is primary; descriptions, status lines and category lists sit above the main content in all four.
  • Sort for the activity charts was a filter-style select with Apply in all four; the live site uses buttons that sort at once.
  • Predictions: 1 right (all four used cards that link). 2 right (all four put the filters in the navigation bar). 3 wrong (no build used the light header).
