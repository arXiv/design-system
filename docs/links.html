Links

.ds-link is the inline text link, and it is the same on every surface: internal tools and public pages take the same Link Blue, the same visited purple and the same underline rule. There is no accent-coloured link anywhere — the accent tells a reader which tool they are in, and a link that changed colour with it would stop being recognisable as a link.

The four states

Default is Link Blue with a 2px-offset underline. Hover deepens the color (no underline thickness change — kept subtle to avoid layout shift). Visited shifts to Visited Purple. Focus shows the 3px Link Blue ring via :focus-visible.

Note

Every state here is real: follow the visited example once and it keeps the visited colour.

.ds-link
The same class in body text and in secondary text. The link keeps Link Blue on both; only the surrounding text changes colour.

Inline body links must be underlined

Color contrast against body text is only 3.0:1 in light mode — too marginal to rely on alone. Underlines are mandatory for inline links per DESIGN-POLICIES.md and WCAG 1.4.1 (use of color). Standalone navigation links (header, footer, button-like surfaces) may omit the underline.

Accessibility essentials

  • Say where the link goes. The link text on its own must make sense to someone who hears only the links on the page: “Endorsement policy”, not “click here”, “here” or “read more”. Put the name of the destination inside the <a>, not beside it.
  • A link always has an href. Without one the element is not focusable, has no visited state, and does not announce as a link. Something that acts on this page rather than going somewhere is a button, not a link with a click handler.
  • Keep the underline in body text. Do not set text-decoration: none on an inline link. The underline is the only cue that survives forced-colors mode and a reader who cannot see the colour difference. Only a standalone link, such as one in navigation, may drop it.
  • Keep the visited colour in content. Do not override :visited on links to papers, listings or references. Suppress it only where “where have I been” carries no meaning, such as a breadcrumb or a menu.
  • Do not remove the focus ring. The stylesheet draws it on :focus-visible, so it appears for keyboard users and not on mouse click. An outline: none on a link takes it away for everyone.
  • Say when a link leaves the page or opens a new tab. Open links in the same tab unless the reader would lose work in progress. When a link does open a new tab, or goes to another site, put that in the link text, for example “(opens in a new tab)”, so it is read out with the link and survives page translation.

Rules

Disabled state

Use --ds-text-disabled (#b0aba6) for the disabled color and set pointer-events: none. The underline stays so it is still recognisable as a (currently-unavailable) link. The disabled state falls below AA on contrast — WCAG exempts disabled controls from contrast requirements.

Visited memory

The Visited Purple is intentionally strong, not a faint after-state. Researchers reading long bibliographies and listings benefit from seeing what they have already followed up on; a too-subtle visited treatment defeats the purpose. If a specific surface (e.g., a navigation breadcrumb) needs to suppress visited styling, override :visited { color: inherit } locally.

Spec

Tokens

Four interactive states — default, hover, visited, focus — driven by --ds-link, --ds-link-hover and --ds-link-visited, with the dark values arriving through the same token flip as everything else. Per DESIGN-POLICIES: an inline body link is underlined; a standalone link, such as one in navigation, may omit it.

Read at runtime from design-system.css via getComputedStyle, so the values and ratios are those of the mode that is active. Use the theme control in the header to see the other mode. Contrast is measured on --ds-surface: 4.5:1 AA for the three text colours, and the 3:1 floor for the focus ring, which is a non-text cue.
