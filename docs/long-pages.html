Make a long page navigable

A page that readers scan, come back to or link into, such as a paper or one of these docs pages, needs a way to see its sections, move between them, link to one and get back after a jump.

Contents
  1. Where it is used
  2. The parts
  3. A long page

Where it is used

  • HTML papers.
  • These docs pages.
  • Any long page of text, such as a help page or a policy.

The parts

In the order a reader meets them. Each part is documented on its own page; this page puts them together. This page is an example: its TOC bar is above, and each heading has a Permalink control.

  1. A skip link, first on the page, to the main content. A paper has a second one, to its first section, past the sidebar. See Site header.
  2. The page heading, then section headings in order. A screen reader user moves through a long page by its headings, as through a contents list. See Typography.
  3. The TOC bar, under the page heading: the list of sections, which marks the one being read. See Progressive disclosure. On a paper the bar also holds the arXiv logo and the paper's formats; see Papers.
  4. A link to each section: a Permalink control on its heading, so a reader can point a colleague at the exact place. See Links and, on a paper, Papers.
  5. A way back after a jump, when a link moves the reader to another part of the page. See Show a reference without losing the reader's place.

Rules

A long page

  • A long page has all five parts, in that order. Each answers a different need: passing the header, scanning, moving, sharing a place, and returning.
  • The contents list repeats the page's headings exactly, in the same words and the same order.
  • One sticky bar, and only on a long page. The TOC bar is that bar. See Design policies.
