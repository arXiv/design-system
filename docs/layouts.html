The page container

Every page sits in .ds-container. It centres the content in a column at the standard reading width, 850px at most, with a margin of at least 24px on each side. For a band that runs edge to edge, see Full-width bands.

<main class="ds-container">…</main>

.ds-container places every direct child in the reading column and puts --ds-space-section (48px) between them, so a section has no margin of its own, and nor does a note placed between two sections.

  • One width per page. Everything on a page has the same left and right edge. A dense internal tool may use the wide page; nothing else changes the width.

Sidebar

A sidebar sits to the right of the main column and contains supplementary content. If the content is secondary, distinct from the main content, and it is important that it not be pushed far down the page, then a sidebar is appropriate.

The sidebar has a border and no background. Space separates it from the reading column, and a line separates its blocks from each other.

.ds-sidebar
On an <aside> with an aria-label (see Accessibility essentials). Its parent becomes the two-column layout, with the main content taking the spare width, the sidebar 17rem wide, and --ds-space-section between them. A border frames it, with 8px inside (--ds-space-2), and a line separates its blocks, 16px apart (--ds-space-4). Its text is 13px. Nothing in it is sticky.
<aside>
The sidebar comes after the main content in the markup. When the two no longer fit side by side, the sidebar wraps below the content at full width, 24px below it (--ds-space-6), and a screen reader meets the article first.
.ds-acc
An accordion inside the sidebar is the same ruled accordion as anywhere else, a step smaller to match the sidebar's text, and single-column for the narrow measure. Several in a row go in a .ds-acc-stack. No extra class.
  • Use a sidebar next to content that will have a similar height as the sidebar.
  • When the main content needs the width or is much longer or shorter, use a different content organization pattern. See Where secondary content goes.
  • The sidebar sits next to and starts level with a text block. To aid readability, put page headings and other one-line content above the sidebar so they have the width they need to wrap.

Marginalia and gutter space

At wide screen widths, our max content width leaves enough gutter space on the sides for marginalia. A short note beside the block it belongs to is appropriate for annotation-style content. At narrower widths, it is hidden in an info icon in the block’s top-right corner. Try it by widening and narrowing your screen.

Note

A margin note is one or two sentences. Anything longer belongs in the main content.

The block the note belongs to: a paragraph, a figure, a table or a card. Any block works once it is positioned (position: relative); a card already is.

Relevant code 
<div class="ds-card">
<details class="ds-marginalia">
  <summary><svg aria-hidden="true">…</svg><span class="is-sr-only">Note</span></summary>
  <p class="ds-marginalia-body ds-annotation">The note.</p>
</details>
…
</div>
.ds-marginalia
The note, a <details>. Its first child in the block, so it is read before the thing it annotates. The block supplies position: relative; .ds-card already does.
.ds-marginalia-body
The text, with .ds-annotation for the voice. In the margin it has no chrome; folded, it opens as a small panel under the mark.
.is-sr-only
Required on the mark. The icon is aria-hidden, so without it the control announces as nothing.
  • No JavaScript required. Even the info links use a native disclosure.
  • The marginalia appear at 1314px width. The page width plus a note and its gaps on each side. Below that width, marginal notes are hidden behind an info icon.
  • A note should never contain required information. A reader on a narrow screen may never open or see it, so annotations must contain only optional content.

Accessibility essentials

  • One main landmark. Put the page's content in a single <main>. A page with two, or with none, gives a screen-reader user nothing to jump to.
  • Label every aside. A sidebar is an <aside> with an aria-label that says what it holds, so it announces as a complementary landmark with a name, not as part of the article.

Modifiers

Full-width bands

.ds-full lets a direct child of the container run edge to edge, while its own content lines up with the reading column. It adds no background color of its own.

<main class="ds-container">
  <div class="ds-full">…</div>
</main>

Secondary zones

The default page background is white, and that is the color that primary page content sits on. The secondary zone is a tinted band for what introduces or supports that content: the opening of the page, and any closing material.

A zone is optional. Without one, the whole page is on the page ground, --ds-canvas (white in light mode).

The secondary zone is a direct child of the container marked .ds-full. A page zone band is colored by .ds-zone-secondary.

The opening of the page, in a secondary band.

The thing the page is about, on the page ground.

Closing material, in a secondary band.
Relevant code 
<main class="ds-container">
  <div class="ds-full ds-zone-secondary">               <!-- tinted: introduces -->
    <header class="ds-page-header">
      <h1>Page title</h1>
      <p>One to five sentences that say what the page is for.</p>
    </header>
  </div>
  <section>…</section>                                  <!-- page ground: the thing itself -->
  <div class="ds-full ds-zone-secondary">               <!-- tinted: supports -->
    <section>…</section>
  </div>
</main>
.ds-page-header
The page title, an <h1>, and its introduction, a plain paragraph with no class of its own. These docs pages mark theirs .ds-section-desc, which only flags a summary for the docs' digests; a product page leaves it out.
.ds-zone-secondary
Goes on a .ds-full band and gives it the tinted ground and its own top and bottom padding. A band that opens or closes the page runs to the container’s edge. The colour is the token --ds-zone-secondary-bg: the class is what you write, and the token is the colour the class applies, which changes in dark mode.
.ds-full
On a direct child of .ds-container. The child runs across all three columns, from edge to edge, and its padding brings its own content back in line with the centre column. It has no background of its own.
  • The opening band holds the page title, then an introduction or, on a data view, the filter for the whole page; never the title alone. A title on its own in a tinted band looks unfinished and takes height the reader does not need. An introduction is one to five sentences. A page with neither has no opening band, unless its set uses one; then it needs an introduction.
  • A TOC bar hangs from the opening band's bottom edge. So a page with a TOC bar has an opening band, and an introduction in it. A paper is the exception: its TOC bar holds the paper's tools and sits under the site header (The TOC bar on a paper).
  • Never a band across the main content. A band between two parts of the main content interrupts the reading.
  • On an admin tool or a data view, where the reader needs to find and act on content quickly, a tinted band pushes the main content too far down the page. Separate content with spacing and headings instead; the opening band is the only band.
  • Only a direct child can run full width. .ds-full works on children of .ds-container; nested deeper it does nothing.
  • Do not build a full-width band with negative margins and 100vw. .ds-full measures the container, so it fits exactly; see DESIGN-POLICIES, Never size a full-bleed band in viewport units.

Wide page

A dense internal tool can use a wider page: 1080px instead of 850px. Use it for tables and filters that do not fit the standard width, not for prose.

<main class="ds-container ds-container--wide">…</main>

.ds-container--wide sets the reading column to --ds-width-wide (1080px). Full-width bands follow it.
