Tables

Base data table, sortable column headers, and filter toolbar patterns used across the admin console and arXiv Check.

The base table

The .ds-table class provides warm-tinted header row, subtle row dividers, and hover highlighting. Condensed uppercase headers use IBM Plex Sans Condensed.

Submission type badges

The Type column above uses .ds-badge. The four types, their classes and why they do not take the status palette are on Tags, beside the other small labelled things it is easy to confuse it with.

Usage

Apply .ds-table to the <table> element. Add table-layout: fixed inline when fixed column widths are needed. Use .ds-table-footer on a <div> below the table for row counts or pagination.

Sortable column headers

Add .sortable to a <th> to make it clickable. Place a <span class="sort-arrow"> inside for the direction indicator. Apply .sort-asc or .sort-desc to the <th> to indicate current sort state.

Sort indicator states

  • Unsorted — arrow shows ⇕ in --ds-border-strong #8b8680 (3.12:1 on the header background)
  • Ascending — .sort-asc on <th>, arrow shows ↑ in #1c1a17
  • Descending — .sort-desc on <th>, arrow shows ↓ in #1c1a17

Interaction

Clicking a sortable header toggles through: descending → ascending → descending. Clicking a different column resets the previous column to unsorted. Sort logic is application-specific; the CSS only handles visual states.

Filter toolbar

The .ds-filter component provides a minimal underline-only <select> for filtering data. Typically placed in a toolbar row above or alongside a table. The custom chevron replaces the native dropdown arrow for visual consistency.

Usage

Wrap a <label> and <select> in <div class="ds-filter">. The select gets an underline-only border, custom chevron via background-image, and a focus ring matching var(--ds-focus-ring). Place the filter in a flex toolbar above or alongside the table.

Accessibility

Always associate the <label> with the <select> via for/id. Add aria-label on the select if the visible label text alone is ambiguous.

Bulk-action bar layout

action buttons and their descriptive text (selection count, "Clear selection") sit on the left; filter dropdowns sit on the right. No background tint behind the action buttons — the bar itself stays neutral. Destructive actions (Remove, Delete) are visually separated from constructive ones and always require a confirmation step. Validated in the admin user-page mockup ("Owned Papers" toolbar).

Selected rows

add .is-selected to the <tr> (the lime tint var(--ds-accent-wash), from the stylesheet) — the tint aids scanability of the selection set (adopted 2026-07-29). Selection state must not rely on the tint alone: the row's checkbox carries the state (WCAG 1.4.1).

Actions disable, they never disappear

when nothing is selected, bulk-action buttons render disabled — not removed. Controls that appear and vanish cost users their bearings. This rule is universal (it also appears in the agent guide's hard rules).
