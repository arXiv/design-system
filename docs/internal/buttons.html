Destructive buttons always require a confirmation step

A dialog, an inline confirm/cancel reveal, or at minimum a clear undo path. Never fire a destructive action on single click without giving the user a chance to reconsider. The button colour signals danger; the UX pattern must back that signal up.

Focus ring note: The simulated focus above uses box-shadow so it is visible inside the table cell. In production, the real rule is :focus-visible { outline: 3px solid var(--ds-focus-ring); outline-offset: 2px; } (#1565c0 light / #64b5f6 dark) — the live demo below shows the real behavior.

Disabled contrast: Disabled states are exempt from WCAG 1.4.3 contrast requirements by spec. The washed-out lime tint on the primary communicates inactivity while staying visually connected to the active state. Avoid using disabled buttons without nearby copy explaining why the action is unavailable.

Light outline border at rest, subtle fill on hover/active. The outline provides a clear click affordance without the visual weight of the tertiary button's solid border. Two color variants, two sizes, and a toggled/pressed state for stateful on/off controls. Tooltip (production): Use the framework tooltip component — OverlayTrigger + Tooltip in React Bootstrap (arXiv Check), or MUI's <Tooltip> (Admin Console). Both surface the label on hover and keyboard focus, which is what we need. Do not rely on the HTML title attribute alone in production — it is used here in this mockup only as a placeholder.

Accessibility checklist: (1) aria-label on every icon button — no exceptions. (2) aria-hidden="true" on the icon element or SVG so screen readers do not announce raw glyph names. (3) For custom SVGs, also add focusable="false" to prevent IE/Edge from making the SVG itself focusable.

Toggle / Pressed state (aria-pressed): Use aria-pressed="true" on icon buttons that represent persistent on/off state — e.g., a filter toggle, a grid/list view switcher, or a "show deleted" control. Set aria-pressed="false" when off (restores default appearance). The filled icon glyph (filled vs outline funnel icon) provides an additional visual signal alongside the pressed style. Constructive and Destructive variants represent single-fire actions (edit, delete) and should not use aria-pressed.

Link-style Button (for low-emphasis actions)

A <button> that renders as an inline text link. For low-emphasis inline actions that do not warrant a boxed button shape. Uses Library Grey (--ds-text-muted) — subtly distinct from body text and clearly readable on both white (5.8:1) and Warm Wash (5.5:1). The underline is sufficient affordance in UI contexts. Hover shifts the underline to lime, signalling interactivity with the brand accent without changing text colour.

Colour decision: .btn-link uses Library Grey (#6b6459), not blue and not the near-black body text. The slightly lighter tone gives the button a subtle distinction from surrounding copy — useful when scanning a dense page — while staying entirely within the neutral palette. No blue needed: the underline communicates interactivity in UI contexts. AA on white (5.8:1) and Warm Wash (5.5:1).

Content hyperlinks (<a> tags): Use --ds-link: #1565c0 (Link Blue Light Mode, 5.74:1 on white — AA ✓). The brand's designated Link Blue (#1e8bc3) is only 3.8:1 and fails AA. Note: Link Blue contrasts with Repository Brown body text at only 3.02:1 — too close to rely on colour alone for differentiability (WCAG 1.4.1) — <a> tags must always be underlined to satisfy the standard.

When to use vs. a tertiary button: Use a link-style button when the action is inline within content or a label, or when adding a box would create visual clutter in a dense layout. Use a tertiary button when the action is part of an explicit action group (e.g. alongside Save and Cancel).

Icon size: icons inside text buttons size at 1.15em (the .btn svg.btn-icon-svg rule) (≈16px at the 14px button base). This is a small but important optical correction — an icon at exactly 14px looks slightly small next to capitalised text.

SVG icons (MUI / custom arXiv): Set width: 16px; height: 16px; flex-shrink: 0 on the SVG element in the component. The gap: 6px from .btn handles spacing automatically.

Loading / Pending State

Cross-cutting — applies to all button types. The spinner uses currentColor so it works on every variant without extra colour tokens.

Always show a label alongside the spinner. "Saving…" is better than a spinner alone — it tells the user what is happening, not just that something is. Use the progressive form of the verb matching the button's action.

Implementation pattern (React): Add is-loading class and the disabled attribute together when the async action fires. Remove both on resolution (success or error). Set a minimum spinner display time of ~300ms to avoid a flash for fast responses.

Screen reader note: The .btn-spinner element should have aria-hidden="true" (as shown). The accessible name comes from the visible label text ("Saving…"). Optionally add aria-live="polite" on a status region to announce completion.

Usage Rules

  • Primary: One per view or modal. Use for the single highest-confidence action (Save, Submit, Confirm). Do not use more than one primary button in the same action group.
  • Secondary: Supporting actions that are readily available but not the main path (Edit, Manage, Add). Can appear in multiples.
  • Tertiary: Low-emphasis utility actions (Cancel, Go Back, View History). Never use for destructive actions.
  • Destructive (solid): Hard-delete and irreversible actions only (Delete, Remove, Revoke). Must always be paired with a confirmation step. Do not use for actions that can be undone.
  • Destructive (ghost icon): Prefer the ghost icon variant (.btn-icon-destructive) for table-row and list-item delete actions. The solid button is appropriate only in dedicated confirmation dialogs or isolated danger zones — not scattered across lists where it creates visual alarm at scale.
  • Icon buttons: Always require aria-label. Use the framework tooltip component (not the HTML title attribute) so the label surfaces on keyboard focus as well as hover.
  • Disabled: Only disable a button when you can communicate why nearby — e.g. "Complete required fields above." Never silently disable without context.
  • Focus ring: Implemented with :focus-visible — appears only during keyboard navigation, not on mouse click. Never suppress with outline: none.
  • Windows High Contrast mode: The outline-based focus ring will be overridden automatically by the OS in forced-colors mode. This is correct and expected behavior — do not compensate for it.
