Site header

The universal arXiv public-page header: announcement band + black bar (.ds-announcement / .ds-site-header), plus the .ds-skip-link utility. Validated against the spinout-header-footer Cloud Run deployment — which covers ONLY these two pieces; nothing below the black bar is approved chrome. (A breadcrumb band was briefly part of this pattern and removed: too shallow to justify the real estate, and its links exist elsewhere on the page.)

Live component

Rendered directly from design-system.css. Resize the window: at ≤599px the nav collapses behind the hamburger (the approved mobile treatment); without JS it wraps to a second row instead — every item stays visible, passing WCAG 1.4.10 reflow at 320px and keeping voice-control working. The header is static — it scrolls away with the page (sticky chrome is reader-only — DESIGN-POLICIES.md).

One component, two surfaces

The bare class is the arXiv header. A property that is not arxiv.org adds .ds-site-header--light, which re-points seven surface tokens and declares no property of its own — so there is no rule in the variant that can lose a specificity argument with the rules above it.

The focus ring is the one to notice: the standard Link Blue ring is invisible against Repository Brown, so the dark surface needs its own. Because it is a token rather than a rule, a property that switches surface gets the correct ring without knowing that it needed to.

Dropdown groups — an optional part

A property whose sections need grouping adds .ds-site-header-dropdown, built on <details> so it opens and closes with no JavaScript. A page may add close-on-outside-click and Esc as enhancement.

The summary sits in the bar and takes the surface tokens, so it is correct on either variant. The menu panel does not: a floating panel is a light surface whichever bar summoned it, the same way a popover is.

The menu anchors to its trigger’s right edge. The logo takes margin-right: auto, so the nav always sits at the right of the bar and a left-anchored menu runs off the viewport on the last item — which is every bar’s last item, not an edge case.

Folding instead of collapsing — --wrap

The default bar collapses behind a hamburger below 600px. A page whose own chrome already owns that gesture cannot use it twice, and the HTML paper is exactly that case: the reader’s contents bar has the menu button there. .ds-site-header--wrap folds instead.

It also gives the bar a centre slot. Three grid columns rather than flex, because flex has no way to keep a centre item centred regardless of what sits either side of it. Put anything in .ds-site-header-center and it stays in the middle of the bar; leave it empty and it costs nothing. Below 48rem the centre takes the full width as a third row, and the bar’s height becomes a floor rather than a fixed value, because a second row needs somewhere to go.

<header class="ds-site-header ds-site-header--wrap">
  <a class="ds-site-header-logo" href="/">…</a>
  <div class="ds-site-header-center">…</div>
  <nav class="ds-site-header-nav">…</nav>
</header>

Measured on the paper mockup: 52px tall at 1280px, 56px at 700px, 89px at 390px and 320px, with the centre slot spanning both columns from 48rem down.

Signed out, and signed in

The bar's last item is the emphasis slot — the only nav item that takes weight. Signed out it says Log in. Signed in it says Account, with the greeting beside it.

Search Submit Welcome Sivaramakrishnan Account
  • One word, and it truncates. The greeting takes the given name only — its first word — because the bar is chrome and a full legal name is more of it than the job needs. Even one word is user data of unbounded length in any script, so it is capped at 14 characters with an ellipsis, as the second example shows. A bar that reflows or overflows on a long name breaks for exactly the people whose names get tested least.
  • The greeting is not a link. It is a statement; the thing you can act on is the Account link beside it. Making the name itself the link would give that link the accessible name “Ada”, which says nothing about where it goes.
  • It is the first thing dropped on a narrow bar. Below 600px the greeting hides and Account stays — the link is the useful half, and the reader already knows their own name.
  • Log out is not in the bar. It belongs on the account page. A destructive-adjacent action one mis-tap from Search is a bad trade for the two seconds it saves.

Keyboard and assistive technology

  • It is a disclosure, not an ARIA menu. role="menu" is for application menus — the kind with arrow-key roving focus and menu items that are not links. A list of links is a disclosure, and W3C's own guidance is to build it this way. Using role="menu" here would make a screen reader promise keyboard behaviour the component does not have.
  • The state comes free. <summary> is announced as a button with an expanded/collapsed state, without a single ARIA attribute. That is most of why this is <details>.
  • Escape closes it and returns focus to the trigger. The second half matters: without it, a keyboard user who opened the menu, tabbed into it and pressed Escape is left holding focus on a link that is no longer visible. Return focus only when it was inside the menu — Escape pressed elsewhere on the page must not move it.
  • It works with JavaScript off. Open, close and keyboard operation are native; outside-click and Escape are enhancements layered on top.

The five-item cap is about arxiv.org, not this component

DESIGN-POLICIES caps arXiv’s own top-level navigation at five items. That is a constraint on the content of one site, not on the header. Other properties carry the navigation their content needs, including grouped menus.

Relevant classes
.ds-site-header
The bar. Bare, it is the arXiv header — arxiv.org cannot forget a class it never has to write.
.ds-site-header--light
Seven token values. No property overrides.
.ds-site-header-logo
The brand slot, image or wordmark. Takes margin-right: auto.
.ds-site-header-dropdown
A <details> group in the bar. Optional.
.ds-site-header-menu
The floating panel. Right-anchored, capped to the viewport.
.ds-panel-label
Group headings inside a menu use the system-wide label, not a bespoke class.
.is-collapsible
The hamburger treatment, for bars that cannot wrap.

Behavior contract

  • The skip link (.ds-skip-link) is the first focusable element on the page, visible only on keyboard focus.
  • Logo alt text and aria-labels say "archive" — the spoken form of "arXiv" (screen readers otherwise produce "ar-zhiv" / Roman-numeral gibberish).
  • The Search control is an <a href="/search"> that JS may upgrade to open a search overlay. Never a dead button — without JS it navigates to the search page.
  • At ≤599px the nav collapses behind a hamburger only after JS enables it: the header script adds .is-collapsible to .ds-site-header and wires the toggle (.is-open on the nav, aria-expanded in sync) in the same call, so the hamburger appears only when it actually works. The default — including no JS — is the wrap (all items visible, WCAG 1.4.10 reflow).
  • Focus rings on the dark bar use --ds-focus-ring-on-dark (#64b5f6); the standard Link Blue ring is invisible against #1c1a17.
  • The announcement is temporal: render only while active, persist dismissal in production, and never attach page-critical function to it.
  • Nothing in this unit is sticky — the whole header scrolls away with the page (; sticky chrome is exceptional at arXiv and reader-only). No scroll-padding duty applies.
  • Type sizes are rem so browser font-size overrides propagate; both bands are hidden in print.
