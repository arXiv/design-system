Indicate which version is being read

A paper can have many versions, and a reader can arrive at any of them from a link. Show which version is open, how it relates to the others and whether the paper has been withdrawn. Version display patterns should be applied consistently on both public and internal pages.

Where it is used

  • A paper's own HTML page or abstract: the version row under the title, and the Version history panel in the sidebar (see Papers).
  • Internal tools that show a paper by version, such as the admin console's paper details.

Version row

Every paper shows its dates under the title, and its versions once there is more than one. What is shown depends on how many versions there are, which one the reader is viewing, and whether the paper has been withdrawn or a version removed.

One version

The most common case because most papers have a single version. We show the submitted and announced dates and nothing else.

.ds-date-row
The row. One <p> that holds the dates and, after them, the version links. Small type in the muted color, with tabular figures so the digits line up.
<time datetime>
Every date. Announced is a full instant (2026-01-11T01:32Z); Submitted and Revised are date-only (2026-01-10). In the visible text, bind the day, month, year and clock time to each other with &nbsp;, and bind UTC to its date the same way, outside the element.
.is-sr-only
The separator. The visible "·" is aria-hidden, and the sr-only comma beside it is what a screen reader gets between one date and the next.

A few versions

Once a paper has more than one version, the date row displays three dates: Submitted and Announced are always the v1 dates; Revised … (this version) is the date of the version you are reading. The versions follow the dates on the same line, after a dot, and wrap with it. Prior versions are text links. The current version is not a link: it is bold, in a box with the accent tint, and includes the aria-current tag.

.ds-version-list
The versions. A <span> at the end of the .ds-date-row, after a dot: every version, oldest first. A taller line and wider word spacing keep the version links 24px apart.
.ds-version
One version number, in the mono face. A prior version is an <a> with an href, and takes the page's link color and underline. The version being viewed is a <strong>, not a link, in a box: the accent tint, edged in the strong accent.
aria-current="true"
On the version being viewed, which draws the box. The current version is marked by the box, the bold and the missing underline, never by color alone. The .is-sr-only span inside it says ", this version", because the attribute alone is not announced by every screen reader.
.is-sr-only
Inside every prior-version link, after the visible "v1": ", version 1". The visible "v1" on its own does not say which version the link opens. A screen reader reads the link as "v1, version 1".

Viewing an older version

When the reader is on anything but the latest version, a few things change.

  • If you are viewing V1, we add (this version) to the submitted date.
  • In all cases, an amber warning appears (not error red or neutral blue) pointing to the current version.

Many versions

Once a paper has ten or more versions we make some additional changes.

  • The inline list keeps its first three and last three and elides the middle with an ellipsis. The elided versions are still in the DOM, but hidden with hidden and aria-hidden.
  • The ellipsis has aria-hidden and a screen-reader-only span beside it says "versions 4 through 9 hidden," so the reader knows there are more versions than they can see.
  • The version being viewed always stays visible, wherever it falls in the list. It may interrupt the ellipsis.
  • A text button displays the total count and expands the full list.
  • The expanded list shows all versions in a list, wrapping if necessary. No javascript required.

.ds-show-more
The control that expands the list, documented on Progressive disclosure. Requires aria-expanded, flipped on every press, and aria-controls naming every region it shows or hides; show-more.js, once per page, does the flipping. The label includes the total: "show all 12 versions", and "show fewer" once open.
.ds-show-more-tail
On the span that holds the elided versions. The full list is in the HTML the server sends: show-more.js hides the tail with the hidden attribute, not a class, so the hidden links are out of the tab order, and shows the button. With no JavaScript the reader gets every version and no button.
[hidden]
On the button and on the span that holds the ellipsis, in the markup: neither means anything without JavaScript. The script shows the ellipsis while the list is closed.
aria-hidden="true"
On the ellipsis, which is decoration. The .is-sr-only span beside it says which versions are hidden. Both sit in one span that the button hides when the list opens.

A withdrawn paper

A withdrawn paper ends with a withdrawal notice in the error colors. The version dates end with Withdrawn and its date. Earlier versions can still be read. The highlight on the version being read turns red only when it is the withdrawn version, the last one before the notice. On an earlier version, the highlight keeps its usual color.

Follows NISO RP-45-2024 §1.2, which states that a retraction notice is “a distinct publication”.

A removed version

arXiv removes a version in place: it keeps its number and its place among the versions, and its dates end with Removed and the date. The highlight on a removed version being read turns red, as on a withdrawn version.

Accessibility essentials

  • Mark the version being viewed. Put aria-current="true" on it, make it a <strong> and not a link, and put <span class="is-sr-only">, this version</span> inside it. Bold alone is invisible to a screen reader, and the attribute alone is not read out by every one.
  • Say which version each link opens. Every prior-version link has <span class="is-sr-only">, version 2</span> after its visible "v2". The visible "v2" does not say which version the link opens, and a screen reader user listing the links on the page hears each one out of context. Use the span, not an aria-label: the link's name has to start with the "v2" that a speech recognition user sees and says, and translation tools do not translate aria-label.
  • Put the warning where it is read early. The older-version warning is part of the page as it loads, so it takes no role (see Alerts); it comes straight after the title and the dates. Render it only when the reader is not on the latest version; an alert that is always there is noise.
  • Separate the dates in words. The visible "·" between dates is aria-hidden="true", and a <span class="is-sr-only">, </span> sits beside it. Without the comma the three dates are read as one run-on sentence.
  • Say what the ellipsis hides. The "…" is decoration and is aria-hidden="true". The .is-sr-only span beside it says which versions are hidden, and the button says the total: "show all 12 versions". Use the hidden attribute on the hidden versions, never a class, so they are out of the tab order while they are off screen.

Rules

Versions

  • Version links go to abstract pages.
  • The dates and the older-version warning stay by the title. The full history goes in the sidebar.
  • Each version shows its own comments, as the author wrote them for that version.

Withdrawn papers

Display guidelines for withdrawn and removed papers follow NISO RP-45-2024. The status before the title, the notice and what leaves the page are in Papers.

  • We use the term “Withdrawal notice” in the version dates and Version history, because that is a more accurate description of its role. The identity line still shows the version number.
  • Red marks a withdrawn or removed version only when it is being read. Any earlier version being read keeps its usual look, and the link to the notice is always red.

Formatting the three dates

Submitted [v1 date] UTC · Announced [announcement date and time] UTC are always shown, in that order, separated by a dot. Announced is when the paper first entered the public listing. Revision dates are when subsequent versions of the same paper went public. Dates use <time datetime>.

Announcement is the date that readers care about the most. It renders as 11 Jan 2026, 01:32 UTC. Submitted and Revised stay date-only to save space.

When only the month of the announcement is known, as in a search index, show the month: Announced Sep 2026, with datetime="2026-09".

arXiv's platform serves a global audience across all timezones. UTC was chosen as the universal standard to ensure consistency and clarity for all users. It is a group decision, made with arXiv staff.

Times are rendered in plain-text UTC bound to its date with &nbsp; so a wrap never separates them. The <time> element is not bound to the date.

Inside datetime, announced is a full instant (2026-01-11T01:32Z), Submitted and Revised stay date-only (2026-01-10).

The version being viewed is distinguished by a box, by weight and by aria-current and does not depend on color alone. It is deliberately not a link because the reader is already viewing it.

Prior versions are inline links alongside other text, so they are underlined. Each also has a hidden span that says which version it opens, so a screen reader reads "v1, version 1".

Formatting the ellipsis and show all toggle

The ellipsis is decoration (aria-hidden) with an sr-only count of what is hidden; the working affordance is a text button showing the explicit total ("show all 127 versions"), toggling aria-expanded. The full list is server-rendered and collapsed by the script in html.js. Without JavaScript, the fallback is that readers see the full list of versions.
