Buttons

Every arXiv button — public and internal — shares one mechanical spec: 6px radius, 10px 20px padding, subtle rest shadow, 1px press drop, 0.12s transitions. What differs is the color, and the color is doing a job: it tells the person which context they are in. Detailed per-context references: public · internal.

One system, two contexts

The primary-action color is set by the context, not by preference (DESIGN-POLICIES, Internal vs. Public pages).

Public — Open Blue

Everything a reader or author sees on arxiv.org: listing, abstract, HTML paper pages. Primary is Open Blue #a5d6fe with Repository Brown text; secondary is white with a warm-grey gradient border.

Internal — Access Lime

Staff-facing tools: the moderation queue, arXiv Check, the Admin Console. Primary is Access Lime #c4d82e; secondary is a lime tint with a lime border.

Never mix the two accent colors

A lime primary on a public page, or an Open Blue primary in a staff tool, is a policy violation. If the context is ambiguous, settle it first and record the answer in a code comment.

Public buttons — Open Blue

Rendered from the real .ds-btn classes in public/design-system.css. Both variants share the V3 construction: a 1.5px gradient border (lighter top → darker bottom) via dual padding-box/border-box backgrounds, plus an inner vignette that darkens the perimeter. Hover brightens, press drops 1px and deepens the vignette.

On tinted surfaces

The primary holds its own on both tint families — its gradient border and vignette keep the edge legible cool-on-cool and cool-on-warm alike. The secondary adapts: on cool tints it takes the .on-tint modifier, which swaps the white fill to Card Grey (same luminance, warm hue) so it reads as secondary by material rather than contrast; on warm tints the default white secondary already sits comfortably.

The quiet tier

A control that does something, dressed as quietly as a link. Use it for actions that are real but minor next to the page's main choice. It borrows the link's quietness, not its identity: Link Blue for the actionable color, but never underlined, and hover is a background wash — the same feedback the other buttons give. Underlines stay with links, so a reader can still tell "this navigates" from "this acts here."

Why there is no outline-only tier: the secondary is already white-fill-plus-border, and on a white page canvas a transparent fill is the same pixels as a white one — the two would differ by a drop shadow, which nobody reads as hierarchy. Each context reaches its quiet tier by removing whatever its secondary uses to hold the page. Public secondary leans on its border, so the text button drops the border. Internal secondary leans on a lime fill, so .btn-tertiary drops the fill and keeps a border. Same rank, different construction, on purpose.

Icons

Any .ds-btn accepts an inline SVG. The stylesheet sizes it in em so it tracks the button's own font-size, blocks the inline baseline gap, and stops it shrinking when the label is long. Stroke icons pick up the button's text color on their own — set stroke="currentColor" and nothing else.

On a committed color field

The sibling of .on-tint, for buttons sitting on a field dark enough to host white text — an outreach masthead, a photo band. The white fill would read as a paper rectangle stuck to the surface, and louder than the primary beside it; .on-dark drops the fill so the field shows through and carries the boundary on a white border. Only correct on dark fields — on a light tint, use .on-tint. See outreach sites for where such fields are allowed.

Buttons in forms

A form ends in a row of buttons, and the only question that row asks is what tier the second button takes. Secondary is for a real alternative path — somewhere the person might genuinely be going; “Go back” is a destination, not an absence. Text is for the null action, which is simply not proceeding: there is no second destination there, only the thing and the absence of it, and a border would set the absence competing with the action for attention.

Every example below is rendered with the public classes, and the same reasoning picks the internal tiers. Field construction, validation, and the accessibility contract for the fields themselves live in Forms & validation.

Which tier the second action takes

The other actionTierWhy
Not proceeding — Cancel, Not nowTextThere is no second destination, so nothing is being ranked. A border would make the absence compete with the action.
A real alternative path — Go back, Save draftSecondaryBoth buttons lead somewhere. The row is ranking two destinations, not offering a way out of one.
A misclick is expensive — backing out discards work, or proceeding is destructiveSecondaryRaise the quiet action's weight when a misclick is expensive. A text button beside a primary is easy to hit by accident, and neither discarded work nor a deleted file comes back. The weight buys a moment of pause.
Three or more actionsA secondary must appearText plus primary carries two ranks and no more. A third action needs a middle, or the row has no readable order.

Button weight is the tool for cheap mistakes. When the mistake is expensive or cannot be undone, the answer is a confirmation step, not a heavier button — arXiv already does this during submission, where deleting files raises a confirmation dialog naming how many files will be deleted. Weighting a button is not a substitute for confirming a destructive action.

Save or cancel

Cancel is the null action: the person either saves the change or does not make it. It takes the text tier, which leaves exactly one thing in the row that looks like a button to press.

Continue or go back

Both buttons lead somewhere. Go back is the previous step of the submission, with the person’s work still in it — a destination, not an absence — so it takes the secondary tier.

When backing out discards work

Discarding is still the null action, but here it throws away everything typed into the form. A text button sits beside the primary with no border to stop a stray cursor, and the mistake cannot be undone, so the null action earns secondary weight anyway.

Three actions — the boundary

None of these three is a null action: going back, saving a draft, and continuing are three places the person can end up. Text plus primary carries two ranks and there are three to show, and a borderless control between two bordered ones reads as a gap rather than a rank — so the row runs secondary, secondary, primary, and separates the backwards step by position instead of by weight.

One action

Some forms have no alternative path and no null action worth a control: the person submits, or leaves the page, which the browser already handles. Adding a Cancel here is a reflex and it is wrong — it invents a second choice and asks every reader to rule it out.

An action that is not available yet

Use aria-disabled, never the disabled attribute: a disabled button leaves the tab order, so a person who cannot proceed finds nothing there and no explanation of why. The requirement goes in a visually hidden element that aria-describedby points at, so it is read out when focus lands on the button. Not a hover tooltip: a tooltip is absent from the accessibility tree at exactly the moment nobody is pointing at it.

Grant the license before continuing.

The flat Card Grey fill is .ds-btn:disabled, .ds-btn[aria-disabled="true"] in the shared stylesheet — one rule for every variant, because the message is “you cannot use this”, which does not also need to encode which button it was. The two selectors render identically on purpose: the difference between them is behavioural, and the reader has no use for it.

A destructive action

Deleting is not the page’s call to action, so it does not get the primary tier, and it does not sit next to the button people press without reading. Color and position each carry part of the warning: .ds-btn-destructive says what the button costs, and the delete still goes to the far end of the row, away from Save.

It is built like the rest of the public set — the same dual-background construction, lit from above — with one departure. Hover holds the fill and lightens the inner vignette instead of brightening the color, because a lighter red drops white text below AA. White on Danger Red #c62828 stays at 5.62:1 through every state.

The red is a warning, not a safeguard

Reserve .ds-btn-destructive for hard-delete and irreversible actions, and always pair it with a confirmation step. The color tells a person what the button costs; it does not stop them pressing it, and it is never the only thing making the action safe.

Add another row

A repeatable group grows on demand — arXiv’s own is “Add top-level file” on the upload page. It is a real action, but a minor one beside whatever the form is for, so it takes the text tier and sits directly under the group it extends.

Remove one row

The inverse control belongs inside the row it removes, not in the form’s action row: it acts on one item, not on the form. Text tier again, and the accessible name says which row it removes — a column of buttons all reading “Remove” is a list of identical choices to anyone reading them one at a time.

While the submit is in flight

The button reports its own work: the label changes to say what is happening, and a spinner marks the wait. Keep the same button in the same place — replacing it with a message throws away the keyboard focus that is sitting on it. The button is working, not unavailable, so it carries aria-busy rather than aria-disabled and keeps its live rendering; the handler is what ignores a second press.

The label is the state, so it changes in the markup and not only in CSS — a spinner alone announces nothing. Under prefers-reduced-motion: reduce the ring stops turning and the label carries the state on its own (DESIGN-POLICIES, Motion).

Usage

<!-- Null action: text + primary -->
<button class="ds-btn ds-btn-text" type="button">Cancel</button>
<button class="ds-btn ds-btn-primary" type="submit">Save</button>

<!-- Real alternative path: secondary + primary -->
<button class="ds-btn ds-btn-secondary" type="button">Go back</button>
<button class="ds-btn ds-btn-primary" type="submit">Continue</button>

<!-- Not available yet: aria-disabled, with the reason described -->
<span class="is-sr-only" id="gate">Grant the license before continuing.</span>
<button class="ds-btn ds-btn-primary" type="submit"
        aria-disabled="true" aria-describedby="gate">Continue</button>

Accessibility notes

  • Contrast. Repository Brown on Open Blue #a5d6fe and Repository Brown on Access Lime #c4d82e both pass AA for normal text. White on danger #c62828 is 5.62:1 ✓. Bottom border-gradient hover stops pass the 3:1 UI-component minimum (3.89 / 3.61); the rest-state stops sit below it and are decorative — the button's fill and border carry the boundary at rest.
  • Focus. :focus-visible, never :focus — the ring shows on keyboard nav only.
  • Not color alone. Hover changes fill AND border AND vignette; press changes position AND shadow (WCAG 1.4.1).
  • Target size. Standard padding yields ~37px-tall buttons — above the 24×24 hard floor (WCAG 2.2 SC 2.5.8); aim for 44×44 on touch-primary surfaces.
  • Reduced motion. The only motion is the 1px press drop; wrap transitions in @media (prefers-reduced-motion: no-preference) where a stronger guarantee is needed.
  • Semantics. Real <button> for actions, <a class="ds-btn …"> for navigation. Disabled controls keep cursor: not-allowed.
