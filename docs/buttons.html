Buttons

Every arXiv button — public and internal — shares one mechanical spec: 6px radius, 10px 20px padding, subtle rest shadow, 1px press drop, 0.12s transitions. What differs is the color, and the color is doing a job: it tells the person which context they're in. Detailed per-surface references: public · internal.

One system, two contexts

The primary-action color is set by the surface, not by preference (DESIGN-POLICIES, Internal vs. Public pages).

Public — Open Blue

Everything a reader or author sees on arxiv.org: listing, abstract, HTML paper pages. Primary is Open Blue #a5d6fe with Repository Brown text; secondary is white with a warm-grey gradient border.

Internal — Access Lime

Staff-facing tools: the moderation queue, arXiv Check, the Admin Console. Primary is Access Lime #c4d82e; secondary is a lime tint with a lime border.

Never mix the two accent colors

A lime primary on a public page, or an Open Blue primary in a staff tool, is a policy violation. If a surface is ambiguous, decide its context first and record it in a code comment.

Public buttons — Open Blue

Rendered from the real .ds-btn classes in public/design-system.css. Both variants share the V3 construction: a 1.5px gradient border (lighter top → darker bottom) via dual padding-box/border-box backgrounds, plus an inner vignette that darkens the perimeter. Hover brightens, press drops 1px and deepens the vignette.

On tinted surfaces

The primary holds its own on both tint families — its gradient border and vignette keep the edge legible cool-on-cool and cool-on-warm alike. The secondary adapts: on cool tints it takes the .on-tint modifier, which swaps the white fill to Card Grey (same luminance, warm hue) so it reads as secondary by material rather than contrast; on warm tints the default white secondary already sits comfortably.

Accessibility notes

  • Contrast. Repository Brown on Open Blue #a5d6fe and Repository Brown on Access Lime #c4d82e both pass AA for normal text. White on danger #c62828 is 5.17:1 ✓. Bottom border-gradient hover stops pass the 3:1 UI-component minimum (3.89 / 3.61); the rest-state stops sit below it and are decorative — the button's fill and border carry the boundary at rest.
  • Focus. :focus-visible, never :focus — the ring shows on keyboard nav only.
  • Not color alone. Hover changes fill AND border AND vignette; press changes position AND shadow (WCAG 1.4.1).
  • Target size. Standard padding yields ~37px-tall buttons — above the 24×24 hard floor (WCAG 2.2 SC 2.5.8); aim for 44×44 on touch-primary surfaces.
  • Reduced motion. The only motion is the 1px press drop; wrap transitions in @media (prefers-reduced-motion: no-preference) where a stronger guarantee is needed.
  • Semantics. Real <button> for actions, <a class="ds-btn …"> for navigation. Disabled controls keep cursor: not-allowed.
