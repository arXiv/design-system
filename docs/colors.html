Brand colors

arXiv's core post-spinout identity, grouped by the role each color plays. Primary and secondary carry the brand; support colors do the quieter structural and accent work.

Note

The three warm greys form a deliberate ladder, one stop per contrast tier: Disabled, UI Boundary, Library. Do not introduce intermediate values without a DESIGN-POLICIES.md change.

Primary

  • Open Blue #a5d6fe --ds-accent

    arXiv's primary brand color. Public primary actions (HTML/PDF buttons), highlights, section accents.

  • Repository Brown #1c1a17 --ds-text

    Body text, dark backgrounds, primary headers. The text workhorse — clears AA on every approved surface.

Secondary

  • Archival Blue #1f5e96 --ds-accent-strong

    Brand accent blue; public section headings.

    6.8:1 on white ✓ AA

  • Library Grey #6b6459 --ds-text-muted

    Secondary text, labels, muted interactive elements.

    5.83:1 on white ✓ AA

Support

  • UI Boundary Grey #8b8680 --ds-border-strong

    Interactive borders, tracks, arrows.

    3.61:1 on white ✓ 3:1 UI

  • Disabled Grey #b0aba6 --ds-text-disabled

    Disabled states only — exempt from contrast requirements.

    2.24:1 — below AA, by design

  • Smileybones Yellow #ffe000 --ds-brand-smileybones-yellow

    The smileybones mascot; celebratory and playful contexts; callout fills; horizontal rules framing an image on outreach properties. Fails text contrast — fills and graphics only.

    ~1.3:1 — fills only

Heritage — used sparingly

  • Campus Red #b31b1b

    The X in the logo mark; very occasional accent. Never headers, buttons, large fields, or text. No token: it is drawn in the logo, not written in a stylesheet.

  • Publishing Pink #fb595a

    Rare: time-limited announcements, celebratory accents. Never errors or body text. No token.

Open Blue on a public page. The fill of the primary button and of highlights; inside .ds-internal the same token is Access Lime.
--ds-text-on-accent
Repository Brown, fixed in both modes: the text colour on an accent fill. Nothing else clears AA on Open Blue.
--ds-text
Repository Brown. Body text and headings on every surface. Flips to a light value in dark mode.
--ds-text-muted
Library Grey. Secondary text, labels, and captions. Still AA on every approved surface except Grey Active.
--ds-accent-strong
Archival Blue. Section headings and the on state of a switch. Not a link colour.
--ds-border-strong
UI Boundary Grey. The edge of a control: input borders, switch tracks, arrows. Never for text.
--ds-text-disabled
Disabled Grey. The label of a disabled control and nothing else.
--ds-brand-smileybones-yellow
Smileybones Yellow. Fills and thick rules only; it holds its value in dark mode.

Internal accent

  • Access Lime #c4d82e --ds-accent

    Internal primary-action identity — signals "you are in an internal tool." Not used on public pages. Fails text contrast — fills only.

    ~1.5:1 — fills only

Relevant code 
<!-- An internal tool puts the class on the root; the accent follows -->
<html lang="en" class="ds-internal">

background: var(--ds-accent);        /* Access Lime inside .ds-internal */
color: var(--ds-text-on-accent);
.ds-internal
Re-points --ds-accent and the button colours to Access Lime for everything inside it. An internal tool puts it on <html>; a page that shows both surfaces puts it on a wrapper.
--ds-accent
Access Lime inside .ds-internal, Open Blue everywhere else. The same token name on both surfaces, so a component never has to know which one it is on.

Do not cross Open Blue and Access Lime

Access Lime never appears on public pages; Open Blue never on internal tools. The color difference is functional and quickly informs the user staff which context they are working in.

Links and interactive

Colors that signal "you can act on this." Link-vs-body contrast fails 3:1, so inline links are also underlined — color is never the only signal (WCAG 1.4.1).

Text links

  • Link Blue #1565c0 --ds-link

    All interactive links, light mode. Author names, category links, DOIs.

    5.74:1 on white ✓ AA

  • Link Hover #1050a0 --ds-link-hover

    Link hover state.

    7.83:1 on white ✓ AAA

  • Visited Purple #7b2fbe --ds-link-visited

    Visited link state.

    7.02:1 on white ✓ AAA

Focus indicators

  • Focus Ring #1565c0 --ds-focus-ring

    Keyboard focus indicator on light surfaces.

  • Focus Ring on dark #64b5f6 --ds-focus-ring-on-dark

    Required on Repository Brown surfaces, where the standard ring is invisible.

Relevant code 
a { color: var(--ds-link); }
a:hover { color: var(--ds-link-hover); }
a:visited { color: var(--ds-link-visited); }

:focus-visible { outline: 3px solid var(--ds-focus-ring); outline-offset: 2px; }

/* On the dark chrome bar the light-mode ring disappears */
.ds-site-header :focus-visible { outline-color: var(--ds-focus-ring-on-dark); }
--ds-link
Link Blue. Every inline and standalone link, and the text button. Flips to a lighter blue in dark mode.
--ds-link-hover
Link Hover. The hover and active colour of a link.
--ds-link-visited
Visited Purple. A link the reader has already followed.
--ds-focus-ring
The keyboard focus outline on every light surface. Use it with :focus-visible, never :focus.
--ds-focus-ring-on-dark
The focus outline on the dark chrome bars (--ds-chrome), which are dark in both modes.

Success is lime-olive, not forest green — arXiv has no success-green, and introducing one would loosen the palette. Info is navy, deliberately darker than Link Blue so banners are never mistaken for links. The error border is Danger Red #c62828 — the functional color for destructive actions and error states everywhere, deliberately distinct from heritage Campus Red. Backgrounds and tints

Tints for section depth without hard borders, plus the light-blue surfaces arXiv lays over paper content. Picking one and staying accessible on it are covered under Rules below.

Background tints

Barely-perceptible tints for section depth without hard borders. Mostly warm (Repository Brown stepped toward white), with a cool wash and a code-block blue tint for jobs that read better cool.

  • Warm Wash #f9f7f7 --ds-canvas

    Footer, metadata bands, internal page background

  • Cool Wash #f7fafc

    Cool section differentiation. No token.

  • Grey Hover #f0eeec --ds-surface-muted

    Hover fills, Related band, reader header

  • Grey Active #e4e0db --ds-border-muted

    Active fills, pill borders, footer edges

  • Border Light #ddd8d2 --ds-border

    Component hairlines — inputs, tracks, card edges. Decorative only (below 3:1); never the sole boundary of an interactive control.

  • Blue Tint #f0f5ff

    Code and identifier backgrounds. No token.

Relevant code 
background: var(--ds-canvas);         /* the page ground */
background: var(--ds-surface);        /* a card, a raised panel */
background: var(--ds-surface-muted);  /* a secondary band, a hover fill */
border: 1px solid var(--ds-border);   /* a decorative hairline */
--ds-canvas
Warm Wash. The page ground behind everything.
--ds-surface
White. Cards, panels, and the primary zone of a page. In dark mode it becomes a raised dark surface, not white.
--ds-surface-muted
Grey Hover, also called Card Grey. A secondary band one step down from the page, a hover fill, the disabled button fill.
--ds-border-muted
Grey Active. The deepest warm band: pressed fills, pill borders, the footer edge. Body-size grey and links miss AA on it.
--ds-border
Border Light. A decorative hairline on inputs, cards, and tracks. Below 3:1, so never the only edge of a control.

The arXiv Chrome family — Open Blue's tints

Open Blue stepped toward white (plus its hover step #c2e2ff): light blues reserved for arXiv-added chrome layered over content — popovers, the TOC dropdown, active inline states, the read-aloud highlight, the reader footer band. The recognizable rule: light blue = arXiv chrome speaking, not the paper. (PROPOSED-GUIDELINES.md G4.)

  • Tint Light #edf4fc --ds-accent-surface

    Popover, dropdown, and footer-band surface

  • Tint Border #c4dcf0 --ds-accent-border

    Matching panel edge

  • Active Wash #d6e8f7 --ds-accent-wash

    Active inline states; hover within panels; read-aloud highlight

  • Open Blue Bright #c2e2ff --ds-accent-hover

    Hover state for Open Blue primary fills

--ds-accent-surface
Tint Light. The ground of a popover, a dropdown, the reader footer band.
--ds-accent-border
Tint Border. The edge of that panel. Inside .ds-internal it is the lime border instead.
--ds-accent-wash
Active Wash. The deepest chrome blue that still holds AA for body text: an active inline anchor, a hover inside a panel, the read-aloud highlight.
--ds-accent-hover

Accessibility essentials

  • Use tokens, not hex values. Take every color from a --ds- token. The hex values on this page are specimens to read, not values to paste into a stylesheet. A color with no token is not available to build with.
  • Check contrast on the actual ground. A color that passes on white can fail on a tint. Body text needs 4.5:1; large text and the edge of a control need 3:1. The tables under Spec show which text tokens are safe on which surface.
  • Never use color alone. Pair a color with a word, an icon, an underline, or a change of position, so a reader who cannot see the color still gets the message (WCAG 1.4.1).
  • Dark mode flips the tokens. Every token on this page takes its dark value on its own. Never hand-pick a dark value into a page; see Dark mode for what flips and what stays fixed.

Working on tinted backgrounds

"No one-off hex values" has three tiers. Tier 1 — palette tokens (everything on this page): free to use in their documented roles. Tier 2 — component-internal constants: a handful of values that exist only inside a component's own CSS — the button-border gradient stops, the dark header's hover and divider shades. They are part of those components, not the palette; do not lift them for new uses. Tier 3 — everything else: does not exist. If a new value seems needed, it is a color-mapping.md change, not a local invention.

Recommended pairings

The recommended set — what to reach for on each surface. It is deliberately not exhaustive: any pairing not listed here, and any new tint, must be checked against WCAG AA before use (4.5:1 normal text; 3:1 large text and UI boundaries).

Buttons change clothes on tinted surfaces

The secondary button's white fill reads as "primary" against a tinted band, so tinted sections add the .on-tint modifier: the fill swaps to Card Grey — same luminance as the surface, warm hue — so the button reads as secondary through warm-on-cool material difference, not through low contrast. Which text is safe on which surface

Three shipped bugs were text elements borrowing tokens from non-text roles — the paper watermark used the disabled tier, the skip link paired a flipping background with a fixed white, and the nav group labels used the border tier. This table is the positive answer: the pairings that clear WCAG AA in both modes. It is generated from the stylesheets by verification/check-contrast.py, which also fails if the table and the tokens ever disagree — regenerate it, do not hand-edit it.

Each passing cell renders its own pairing in your current mode; the numbers are the measured contrast in light / dark. ✗ marks a ratio below WCAG AA for normal text (4.5:1). Large text (24px, or 18.66px bold) only needs 3:1, so a ✗ cell may still be usable for headings — check the number.
