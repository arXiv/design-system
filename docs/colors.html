Two contexts — never crossed

Public pages — clean, fast, brown-and-blue

Researcher-facing, content-first, minimal chrome. Color comes from the logo, links, and subtle tinted bands.

  • Primary buttons: Open Blue #a5d6fe
  • Toggles on-state: Link Blue #1565c0
  • Section bands: Warm Wash → Grey Hover → Grey Active

Internal tools — warm, utilitarian, lime-accented

Staff-facing workspaces (arXiv Check, Admin Console). Access Lime signals "you are in a staff tool."

  • Primary buttons: Access Lime #c4d82e
  • Secondary: lime tint #f0f9e8, border #9cb522
  • Toggles on-state: lime green

Do not cross the accents. Access Lime never appears on public pages as an interactive color; Open Blue never on internal tools. The color difference is functional — it tells staff which context they are working in. (DESIGN-POLICIES.md)

Success is lime-olive, not forest green — arXiv has no success-green, and introducing one would loosen the palette. Working on tinted backgrounds

"No one-off hex values" has three tiers. Tier 1 — palette tokens (everything on this page): free to use in their documented roles. Tier 2 — component-internal constants: a handful of values that exist only inside a component's own CSS — the button-border gradient stops, the dark header's hover and divider shades. They are part of those components, not the palette; do not lift them for new uses. Tier 3 — everything else: does not exist. If a new value seems needed, it is a color-mapping.md change, not a local invention.

Buttons change clothes on tinted surfaces

The secondary button's white fill reads as "primary" against a tinted band, so tinted sections add the .on-tint modifier: the fill swaps to Card Grey — same luminance as the surface, warm hue — so the button reads as secondary through warm-on-cool material difference, not through low contrast. Which text is safe on which surface

Three shipped bugs were text elements borrowing tokens from non-text roles — the paper watermark used the disabled tier, the skip link paired a flipping background with a fixed white, and the nav group labels used the border tier. This table is the positive answer: the pairings that clear WCAG AA in both modes. It is generated from the stylesheets by verification/check-contrast.py, which also fails if the table and the tokens ever disagree — regenerate it, do not hand-edit it.

Each passing cell renders its own pairing in your current mode; the numbers are the measured contrast in light / dark. ✗ marks a ratio below WCAG AA for normal text (4.5:1). Large text (24px, or 18.66px bold) only needs 3:1, so a ✗ cell may still be usable for headings — check the number.
