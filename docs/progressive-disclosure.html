Progressive disclosure

Every way arXiv shows less than it has, and how a reader gets the rest. A paper page holds far more than any one reader wants at once — twenty-two authors, eleven versions, four hundred references, the full licence text — and the choice is never whether to hide something but which affordance does the hiding, because each one makes a different promise about what is behind it.

Which affordance

The question that separates them is not how much is hidden. It is what relationship the hidden thing has to what the reader is looking at.

UseWhen the hidden content isCosts the reader
Accordion
.ds-acc		 A labelled section the reader can decide about from its label alone — Versions, Paper information, Related. One click, stays on the page, keeps their place.
Show more
.ds-show-more		 The tail of something already begun — authors nine through twenty-two, the rest of a category list. There is no label to give it, because it is not a different thing. One click, expands in place, no new surface.
Popover
.ds-popover		 A lookup the reader wants without leaving their sentence — what reference 47 is, what footnote 3 says. Nothing permanent. It closes on Escape and does not move the page.
A link to a full page Something with its own identity — a different paper, an author's other work, the full licence. Leaves the page. Pay this only when the destination deserves a URL.
  • Never put must-see information only behind a disclosure. The older-version warning appears in the main column even though the full history lives in the Versions accordion. A reader who never opens anything must still meet everything that matters.
  • Disclosure is not a fix for too much content. If a page needs six accordions to be tolerable, the page has a structure problem and hiding things postpones it. Ask what can be cut or moved before asking what can be collapsed.
  • Default state is closed, except that a single most-relevant panel may start open. Open state is not persisted — predictability beats memory here.

Accordion

Native <details>/<summary>. No JavaScript, keyboard and screen-reader behaviour for free, and the browser's find-in-page can open a closed panel to show a match inside it — which no hand-built accordion does. A +/− glyph replaces the default marker. Four dressings, one element, differing only in how much of the page they are willing to take.

Ruled — .ds-acc-flush

The default choice for a list of disclosures in running content. No box, no fill, no horizontal padding: the label sits on the same left edge as the prose around it, with a rule above and below. One rule would read as a heading with an underline. Two give the disclosure a top and a bottom, so a reader can see that what appears below the first rule belongs to the label above it.

Rail — .ds-acc-rail

Card chrome dropped: no background, no border, no radius. For a disclosure inside a container that already frames it — the paper page's sidebar, where the rail's own hairline dividers do the separating. Internals go single-column for the narrow measure, and the +/− marker turns Link Blue so a closed disclosure still reads as interactive.

Panel — .ds-acc-panel

The loudest variant, and the only one whose summary is a filled bar you press. For a disclosure that has to be found rather than tucked away — the reference panel under each demo on these documentation pages. Its border is --ds-border-strong rather than the decorative hairline, because on an open page it is the only thing carrying the component and has to clear the 3:1 an interactive boundary needs.

Relevant classes
.ds-acc
The base component — the card dressing.
.ds-acc-body
The revealed region. A <dl> inside it gets the standard metadata layout: condensed-caps <dt> labels beside regular <dd> values.
.ds-acc-stack
The container for several. Supplies the gap, or removes it entirely when the items are .ds-acc-flush and should read as one ruled list.

Usage

<!-- Ruled: the default for a list of disclosures in running content -->
<div class="ds-acc-stack">
  <details class="ds-acc ds-acc-flush">
    <summary>Versions</summary>
    <div class="ds-acc-body">
      <dl><dt>v3 · current</dt><dd>24 Apr 2026</dd></dl>
    </div>
  </details>
</div>

<!-- Rail: inside an <aside> whose hairlines already separate -->
<details class="ds-acc ds-acc-rail">
  <summary>Versions</summary>
  <div class="ds-acc-body">…</div>
</details>
  • The summary is the whole label. Never put a second interactive control inside it — a link or button in a <summary> is reachable but its activation fights the disclosure's own.
  • One panel, one label. If a summary needs a sentence to explain what is inside, the content is not a section and probably wants show-more or a page of its own.

Show more

The other disclosure. An accordion hides a labelled section; this reveals the tail of something already begun. The reader is already reading the thing — the control only says how much of it is left.

Three required attributes

An accordion is <details>, so the browser supplies the semantics. A tail cannot be, because a <summary> would put a heading in the middle of a sentence. So this is a real <button> that has to declare for itself what the browser would otherwise have said.

<ul>…first eight names…</ul><span id="authors-tail" hidden>, …the rest…</span>
<button type="button" class="ds-show-more"
        id="authors-toggle" aria-expanded="false" aria-controls="authors-tail">
  … show all 22 authors
</button>
  • aria-expanded — "false" / "true", flipped on every toggle. Without it the control announces as a button that does something unspecified.
  • aria-controls — the id of the region it reveals.
  • hidden on the region, the attribute and not a class. The hidden names are then out of the tab order and out of find-in-page while they are off screen, and the collapse still works with no CSS loaded at all.

The label counts

“show all 22 authors”, not “show more”. A reader deciding whether to expand is asking how much is behind it, and someone using a screen reader hears the control with no view of the list at all. Return the label to “show fewer” when open.

Why it is grey and italic rather than Link Blue

Everywhere this control is used it sits at the end of a run of links — author names, category links — and a Link Blue “show all 22 authors” is one more link in that run, indistinguishable from a name. It is not a link: it goes nowhere, it changes this page. Reading as a different kind of thing than its neighbours is the whole job. Where the control does not sit among links, that reasoning does not apply and the text button (.ds-btn .ds-btn-text) is the right control instead.

Very long author lists are a third tier, not yet promoted

Above roughly a hundred names, expanding in place dumps the reader into pages of links with the collapse control scrolled out of reach. The mockups answer this with a scrollable region capped in height, with a collapse control at both ends. That pattern is validated in the abstract mockup (open it with ?authors=many) but is specific to the paper surface, so it belongs in the reader stylesheet rather than here. Until that stylesheet exists, treat the mockup as the reference.

Popover

A lookup the reader wants without leaving their sentence: what reference 47 is, what footnote 3 says. It is the only disclosure here that does not move the page — which is exactly why it suits a reader mid-paragraph, and why it is wrong for anything they might want to keep open while they read on.

Reference 47
Ashtekar, A. and Bojowald, M. Quantum geometry and the Schwarzschild singularity. Class. Quantum Grav. 23 (2006). Jump to reference
  • Escape closes it and returns focus to the chip that opened it. A reader who opened it from the keyboard must not be stranded at the end of the document.
  • It closes on outside click and on scroll. The panel is position: fixed, so left open it would follow the viewport while the sentence it belongs to scrolls away.
  • The close control is .ds-close, the same one the alert and the announcement band use. The popover supplies its corner position and nothing else.
  • Never put content here that exists nowhere else. A popover is a shortcut to something already on the page or already at a URL — the reference list, the footnote. It is not a place to store text.

Accessibility notes

  • Prefer <details> wherever it fits. It carries the expanded state, the keyboard behaviour and the announcement without any script, and find-in-page can open a closed panel to reveal a match. A hand-built accordion loses all four, and losing find-in-page on a research site is the expensive one.
  • Hide with the hidden attribute, not with a class. Content hidden by a class that fails to load is invisible but still tabbable, which puts a keyboard user in a place they cannot see.
  • Every custom toggle owns aria-expanded. Its absence is the single most common defect in this pattern: the control announces as a button, does something visible to everyone else, and says nothing.
  • Target size. Summaries clear the 24×24 hard floor (WCAG 2.2 SC 2.5.8); the rail variant reaches it with padding plus a matching negative margin, so the hit area grows with no layout shift. .ds-show-more takes WCAG's inline exception, being a target inside a sentence.
  • Nothing animates. These components have no transitions, so there is nothing for prefers-reduced-motion to switch off. An accordion that animates its height also animates the position of everything below it, which is motion a reader did not ask for.
  • The +/− marker is decorative to assistive technology — <details> already announces collapsed and expanded, so the glyph carries an empty alt text form and is not read twice.
