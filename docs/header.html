Site header

The arXiv public-page header sets the tone for the entire platform: simple, straightforward, and utilitarian. It consists of a dark band with logo on the left, and navigation, search, and account links on the right. An optional, dismissible announcement banner can be displayed above the header. Absolute consistency across all pages is critical.

The header is in transition. Pages on arxiv.org use the transitional header from templates/ now, and will move to the aspirational header after the migration.

Internal pages have their own header and variations, see Internal header for an example.

The bars under the header, such as secondary navigation and steps, are on Navigation.

Transitional header (currently in production)

The header on arxiv.org now. A page includes it from templates/ rather than copying its markup; the templates README says how to install it and what each variable does. On arxiv.org the navigation folds behind the menu button when the window is narrower than 600px.

Aspirational header (post-migration)

The header arxiv.org will move to. It differs from the transitional header in three ways: the bar has a theme control after the navigation; Log in and Account sit outside the navigation, in the account area; and signed in, the bar shows a greeting and an Account menu that holds Log out.

The header unit

Every header has the same regions, in this order: logo, Search (public pages), navigation, tools (optional) and account. The header scrolls away with the page; see On small screens for narrow screens.

On small screens

The header fits itself to the space it has. When the regions do not fit on one row, the greeting goes first, then the navigation folds behind a menu button. On a public bar the tools and the account area fold into the same menu, so the bar keeps the logo, the Search icon and the menu button. An internal bar folds the same way, and keeps its search fields in the bar while they fit; after that they open from a Search button. See Internal header. The transitional header folds its navigation when the window is narrower than 600px.

Note

The script answers to the width of the bar, not of the window, so the phone example folds inside a narrower box on a wide screen. Open the menu to see the folded rows.

header.js
These docs’ fold-by-fit script, docs/header.js, once per page. It finds every .ds-site-header and keeps each one on a single row, with no breakpoint to choose. Without JavaScript the bar wraps onto more rows instead, so nothing is hidden. The templates load their own script, so a page that uses them adds none.
.ds-site-header-nav-toggle, .ds-site-header-search-toggle, .ds-site-header-tools-toggle
The menu button, the Search button for search fields, and the Tools button on a bar without an account area. The script adds each one, so they are not in the markup. Each has aria-expanded and aria-controls, and Escape closes the open region and returns focus to its button.
.is-collapsible, .is-single-menu, .is-greeting-hidden, .is-nav-collapsed, .is-search-collapsed, .is-tools-collapsed, .is-menu-open, .is-search-open, .is-overfull, .is-open, .is-measuring
State classes the script sets on the bar and on an open region. They are never written by hand. .is-single-menu marks a bar with an account area, whose menu holds the navigation, the tools and the account area. .is-overfull lets the bar wrap when even the folded bar is too wide for its space.

Header dropdown menus

A property whose sections need grouping adds .ds-site-header-dropdown, built on <details> so it opens and closes with no JavaScript. A page may add close-on-outside-click and Esc as enhancement. The Account menu is the same component.

Accessibility essentials

  • The skip link comes first. .ds-skip-link is the first focusable element on the page, visible only on keyboard focus, and it goes to the main content.
  • Name the navigation. The bar’s links sit in a <nav> with an aria-label, such as “Main navigation”, so a screen reader user can tell it from the other landmarks on the page.
  • The wordmark is an image with alt text. Logo alt text and aria-labels say “archive” — the spoken form of “arXiv” (screen readers otherwise produce “ar-zhiv” or Roman-numeral gibberish).
  • The account area is not navigation. In the aspirational header it sits outside the <nav>, so a screen reader user who lists landmarks finds only site sections there.
  • Name every search field. A search field in the bar is a <form role="search"> with a <label>, hidden with .is-sr-only if needed, that says what it searches. The placeholder is not the name: it disappears as soon as someone types.
  • Mark the current page in the markup. Put aria-current="page" on the current link in the secondary navigation and in header menus.

Internal header

Each internal tool chooses the search fields, navigation and wordmark its users need; the regions, their order and the rules stay the same. Internal headers use a compact account area, one icon button that opens the account menu, not the greeting and Account menu of the public header. Every internal tool uses an internal logo, not the public one, so the reader can tell they are in an internal tool. The internal stylesheet may re-point the bar’s colour tokens and nothing else.

Sticky header

Internal tools only. Adding .ds-site-header--sticky keeps the bar at the top of the viewport while the page scrolls, and the stylesheet sets scroll-padding-top on the page so a link to a section does not land under the bar. A page that uses it keeps no other sticky bar. It is not applied to the examples on this page, which already keeps the TOC bar in view.

Rules

Hosting the header

A page includes the header from templates/ and writes the skip link before it, pointing at its own main content. The templates README says how to install the header, which variables a host sets, and how the stylesheet, scripts and logo are published and cached. Banner announcements says how to put up an announcement.

Design rules

  • Regions, in one order. Logo, search (the Search link on public pages, search fields on internal tools), navigation, tools (optional), account. In the transitional header, Log in or Account is the last link in the navigation, and page actions come after it.
  • Navigation sits on the right. The space after the logo stays empty.
  • No more than four links in arxiv.org’s navigation. The logo and Log in do not count (DESIGN-POLICIES). A host does not change the template’s navigation.
  • Tools hold the theme control and a page’s own actions. The transitional header has page actions only. A control that acts on the page’s data, such as Refresh, goes beside the page heading, with the time the data was last updated.
  • Public search opens on request; internal search stays in view. On arxiv.org, Search is a link before the navigation. Internal tools keep their search fields in the bar while they fit.
  • Log out. Today a signed-in reader logs out on the account page. In the aspirational header, Log out is in the Account menu, one menu away on every page.
  • The greeting is the first name. The aspirational public header shows the given name only, capped at 14 characters. Internal headers use the compact account area, with the name in its menu.
  • Sticky on internal tools only. arxiv.org’s public header scrolls away (DESIGN-POLICIES).
  • No breadcrumbs. arXiv’s sitemap is wide and shallow, so the header navigation and the secondary navigation show the reader’s place.
  • Type sizes are rem, so a reader’s browser font size applies. In print the header keeps only its logo, 28px tall.

Spec

Surface tokens

How the bar is coloured, and how a variant changes it.

.ds-site-header declares seven --ds-hdr-* tokens on itself: background, text, emphasis text, hover, focus ring, bottom border and divider. Every rule in the bar reads one of them, so a variant is a re-pointing of tokens and never a property override: .ds-site-header--light sets all seven and nothing else. A property with its own colours does the same.

The focus ring is the one to notice: the standard Link Blue ring is invisible against Repository Brown, so the dark surface needs its own. Because it is a token rather than a rule, a property that switches surface gets the correct ring without knowing that it needed to.
