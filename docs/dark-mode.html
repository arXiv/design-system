Dark mode

How dark mode works in this system, and what is dark-aware today. The rule that governs everything else: new pages and components are light-only — dark values exist in the stylesheets as foundation, and they flip automatically; nobody hand-picks them.

The mechanism

Dark values live in one @media (prefers-color-scheme: dark) block at the end of each stylesheet, keyed to the OS setting. Any page can opt out and lock to light — every documentation page does:

<html lang="en" data-theme="light">   <!-- locks this page to light -->
  • Tokens flip; components consuming tokens flip for free. Never write a dark hex into a page.
  • Accent colors hold in both modes: Access Lime and Open Blue stay themselves; text on lime uses --text-on-lime (ink in both modes).
  • Anything with color meaning keeps its second cue (icon, word, position) in dark too — WCAG 1.4.1 doesn't pause at night.

Dark-aware today — internal stylesheet

Tokens: surfaces (--surface, --surface-header, --surface-hover, --border), canvas text (--text), grey ladder, link family, lime + secondary families, status families, focus ring. Components riding those tokens: buttons, icon buttons, info card, alerts, forms, data table, sortable headers, filter select, segmented control, toggle, type badges, metadata panel.

Rules

Never hand-pick dark values into a light page

Dark tokens are not an alternate palette to choose from. They flip automatically with the OS, or not at all. A new demo page locks light with data-theme="light"; production surfaces ship light-only until the dark program resumes.

  • Component CSS consumes tokens — never a literal dark hex.
  • A page that deliberately previews dark (like this one's panel, or the alert references) scopes its overrides locally and says so in a comment.
