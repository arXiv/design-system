Tags

The small rounded label for subject categories, topics, and states. One component across all three contexts: .ds-tag in both stylesheets, wearing each one’s tokens.

Four small labelled things, and which is which

The system has four components that are all “a bit of text in a small box”. They are not interchangeable, and the difference is what the text is, not how it looks.

ComponentShowsWhereLooks like
.ds-tag What a thing is — a subject category, a topic, a state. Both surfaces. math.CO Withdrawn
.ds-badge A type. Today that means a submission's type in arXiv Check — new, replacement, cross-list, withdrawal — but the component is not limited to submissions; any other kind of type could use it. Internal tools — table styles. New Rep Wdr Cross
.ds-panel-label The label half of a label/value pair, or a small section heading. Not a box at all. Both surfaces — typography. Submitted

The “pill menus” on HTML papers are not tags. Why?

They are not tags, they are actions — copy a permalink, open the figure large, read the alt text. You can see it without knowing the markup: a tag is a filled pill with a coloured background, and those are white with icon labels. They are documented on Buttons, under Small actions attached to content.

Nor are the inline chips in a paper

A citation marker like [12] or an equation number like (3.4) is not a tag either, and for a different reason: the author wrote it. It comes out of the LaTeX source, and arXiv only makes it navigable — the citation becomes a link, the equation number becomes an anchor. A tag is something arXiv adds to describe content. An inline chip is content, which we layer on top of and never edit (DESIGN-POLICIES).

Why the tag is a pill and the badge is a rectangle

Not decoration. A tag is a standalone object — it may be a link, it may carry a remove control, and it sits in open space where its rounded ends read as one unit. A badge sits inside a dense table row where a pill’s horizontal padding costs column width that the title needs more. Same idea, different pressure.

Why the badge has its own colours rather than the status palette

Because a submission type is a category, not a status. “New” is not success and “Wdr” is not an error — painting them with the status colours would say something untrue about the queue. They carry their own tokens, --ds-badge-*.

The three levels

Prominence comes from color, and only three levels exist. Reach for the quietest one that still does the job.

Quiet — the default

Warm grey. For labels that organize without claiming attention: counts, ancillary labels, anything that is simply true rather than notable.

.ds-tag Preprint 12 requests cs.AI

Chrome — the workhorse

The “arXiv is speaking” blue. For categorizing labels: subject categories, topics, blog post categories. Interactive ones get hover and focus states.

--chrome Policy math.CO Announcements ← that one is a link

Status — only for a real condition

Three of the four alert families. A tag earns a status color only when it reports a condition. A state that is merely neutral, like “under review”, stays chrome: it is information, not an alert. There is deliberately no info variant — it was indistinguishable from chrome, identical in dark mode.

status Valid On hold Removed Under review

In use — the endorsement rows in the admin console

The parts compose. A chrome tag carries a category; a nested .ds-tag-note says where it came from — a username to ask, or --auto for something the system decided; and the error variant carries the whole thing when the endorsement was revoked. Every piece below is a real class.

The type badge

The rectangular one. It marks what kind of thing a row is, inside a table dense enough that a pill’s rounded ends would cost the title column width it needs more. Four, and only four — the palette is fixed in DESIGN-POLICIES (Content and interaction) so a badge means the same thing in every tool that shows one.

BadgeClassMeans
New.ds-badge--newA new submission.
Rep.ds-badge--repA replacement — a new version of a paper already in the archive.
Cross.ds-badge--crossA cross-listing — the paper’s primary category is elsewhere.
Wdr.ds-badge--wdrA withdrawal. Darkest of the four, because it is the one that changes what a reader gets.
  • The abbreviation is the label. It is what the moderation queue has always shown, and expanding it would widen the column for no gain.
  • The palette is its own, not the status palette. A submission type is a category. “New” is not success and “Wdr” is not an error, and painting them with the status colours would say something untrue about the queue. The four carry --ds-badge-* tokens.
  • Today only internal tools show one — see table styles for badges in a live queue. The component is not limited to submissions, and it is in the shared stylesheet, so any surface that needs a type marker in a dense row can use it.

Usage

<!-- A category. Always --keep-case. -->
<span class="ds-tag ds-tag--chrome ds-tag--keep-case">cs.AI</span>

<!-- A topic that links to its listing -->
<a class="ds-tag ds-tag--chrome" href="/list/policy">Policy</a>

<!-- Editable, with a remove control -->
<span class="ds-tag ds-tag--chrome ds-tag--keep-case">physics.optics
  <button class="ds-tag-remove" type="button" aria-label="Remove physics.optics">&times;</button>
</span>

<!-- With a nested provenance badge -->
<span class="ds-tag ds-tag--chrome ds-tag--keep-case">cs.CV
  <span class="ds-tag-note">auto</span>
</span>

Editing affordances are not part of the tag

Drag-to-reorder, the primary marker, and combo-search belong to the category editor, not to .ds-tag. They are designed in the admin-console mockups and get their own pattern page when that work lands.

Rules

Category names are copied, never restyled

Show a category exactly as arXiv publishes it — capitalization included — and always with .ds-tag--keep-case. cs.AI, physics.optics and cond-mat.str-el are all correct as written. Uppercasing the lowercase ones produces strings that are not real categories: every physics.* and cond-mat.* subcategory is lowercase.

A tag never stands in for a link

A tag labels or categorizes the thing it sits on. It may link to a listing, but it must never replace a text link as the way to get somewhere. This is why version links are inline text rather than filled pills.

  • Uppercase is applied with CSS, never typed. The underlying text then stays correct for copy-and-paste, in-page search, and screen readers.
  • Long labels keep their own case. Past roughly three words, or with mixed-case names inside, caps slow reading down — use .ds-tag--keep-case.
  • Color is never the only signal. The label’s own words carry the meaning. A negative or removed state says so in text, not only in red.
  • Not the same as a type badge. .ds-badge stays a 3px rectangle: a compact code in a dense data grid. A tag is a discrete labeled object in a wrapping list.
