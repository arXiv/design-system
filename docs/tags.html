Tags

The small rounded label for subject categories, topics, and states. One component across all three contexts: .ds-tag in both stylesheets, wearing each one’s tokens.

The three levels

Prominence comes from color, and only three levels exist. Reach for the quietest one that still does the job.

Quiet — the default

Warm grey. For labels that organize without claiming attention: counts, ancillary labels, anything that is simply true rather than notable.

Preprint 12 requests cs.AI
Relevant code 
<span class="ds-tag">Preprint</span>
<span class="ds-tag">12 requests</span>

<!-- A category. Always --keep-case. -->
<span class="ds-tag ds-tag--keep-case">cs.AI</span>
.ds-tag
Base. Mono, uppercase, 999px, min-height: 24px for the WCAG 2.2 target floor. Goes on a <span>, an <a>, or a <button>.
.ds-tag--keep-case
Opt out of uppercase. Required for identifiers, and for long labels: past roughly three words, or with mixed-case names inside, caps slow reading down.

Chrome — the workhorse

The “arXiv is speaking” blue. For categorizing labels: subject categories, topics, blog post categories. Interactive ones get hover and focus states.

Note

Announcements is a link, so it takes the hover and focus states; a span never does.

Policy math.CO Announcements
Relevant code 
<span class="ds-tag ds-tag--chrome">Policy</span>

<!-- A category. Always --keep-case. -->
<span class="ds-tag ds-tag--chrome ds-tag--keep-case">math.CO</span>

<!-- A topic that links to its listing -->
<a class="ds-tag ds-tag--chrome" href="/list/policy">Policy</a>
.ds-tag--chrome
The arXiv-blue tint. Categories and topics.
<a>, <button>
A tag that is a link or a button takes its hover and focus states from the element, not from a class. A <span> gets neither.

Status — only for a real condition

Three of the four alert families. A tag earns a status color only when it reports a condition. A state that is merely neutral, like “under review”, stays chrome: it is information, not an alert. There is deliberately no info variant: it would be indistinguishable from chrome, and identical in dark mode.

Valid On hold Removed Under review
Relevant code 
<span class="ds-tag ds-tag--success">Valid</span>
<span class="ds-tag ds-tag--warning">On hold</span>
<span class="ds-tag ds-tag--error">Removed</span>

<!-- A neutral state is chrome, not a status -->
<span class="ds-tag ds-tag--chrome">Under review</span>
.ds-tag--success, .ds-tag--warning, .ds-tag--error
Only when the label reports a condition.

Internal variant

In internal tools, .ds-tag--chrome takes the info palette instead of the accent tints: the accent there is Access Lime, and a lime chrome tag would read as a status. The quiet and status levels do not change.

Policy math.CO Announcements
Relevant code
<html lang="en" class="ds-internal">
  …
  <span class="ds-tag ds-tag--chrome">Chrome</span>
.ds-internal
On <html> for an internal page. The chrome tag inside it takes the info palette; nothing in the markup changes.

Category names are copied, never restyled

Show a category exactly as arXiv publishes it — capitalization included — and always with .ds-tag--keep-case. cs.AI, physics.optics and cond-mat.str-el are all correct as written. Uppercasing the lowercase ones produces strings that are not real categories: every physics.* and cond-mat.* subcategory is lowercase.

A tag never stands in for a link

A tag labels or categorizes the thing it sits on. It may link to a listing, but it must never replace a text link as the way to get somewhere. This is why version links are inline text rather than filled pills.

In use — the endorsement rows in the admin console

The parts compose. A chrome tag carries a category; a nested .ds-tag-note says where it came from — a username to ask, or --auto for something the system decided; and the error variant carries the whole thing when the endorsement was revoked. Every piece below is a real class.

cs.CV auto physics.bio-ph bsmith − physics.gen-ph ginsparg math.AP
Relevant code 
<!-- With a nested provenance badge -->
<span class="ds-tag ds-tag--chrome ds-tag--keep-case">physics.bio-ph
  <span class="ds-tag-note">bsmith</span>
</span>
<span class="ds-tag ds-tag--chrome ds-tag--keep-case">cs.CV
  <span class="ds-tag-note ds-tag-note--auto">auto</span>
</span>

<!-- Revoked: the error variant carries the whole thing -->
<span class="ds-tag ds-tag--error ds-tag--keep-case">− physics.gen-ph
  <span class="ds-tag-note">ginsparg</span>
</span>

<!-- Editable, with a remove control -->
<span class="ds-tag ds-tag--chrome ds-tag--keep-case">math.AP
  <button class="ds-tag-remove" type="button">
    <span aria-hidden="true">✕</span>
    <span class="is-sr-only">Remove math.AP</span>
  </button>
</span>
.ds-tag-note
A small badge nested inside a tag, saying where it came from — usually a username.
.ds-tag-note--auto
The same badge, quieter, for provenance the system set rather than a person. “auto” is a fact about the row; a username is someone to ask.
.ds-tag-remove
The ✕ control inside an editable tag. A <button type="button"> that is the last child of the tag. Removing the tag is the host’s job.
.is-sr-only
Required inside the remove control. The ✕ glyph is aria-hidden, so without this span the button announces as “button” and nothing more. Say what it removes: “Remove math.AP”.

Editing affordances are not part of the tag

Drag-to-reorder, the primary marker, and combo-search belong to the category editor, not to .ds-tag. They are designed in the admin-console mockups and get their own pattern page when that work lands.

The type badge

The rectangular one. It marks what kind of thing a row is, inside a table dense enough that a pill’s rounded ends would cost the title column width it needs more. Four, and only four — the palette is fixed in DESIGN-POLICIES (Content and interaction) so a badge means the same thing in every tool that shows one.

New Rep Cross Wdr
Relevant code 
<span class="ds-badge ds-badge--new">New</span>
<span class="ds-badge ds-badge--rep">Rep</span>
<span class="ds-badge ds-badge--cross">Cross</span>
<span class="ds-badge ds-badge--wdr">Wdr</span>
.ds-badge
The rectangular type marker for a dense table row. Its own palette, not the status one. Always used with one of the four type classes, never alone.
.ds-badge--new
A new submission.
.ds-badge--rep
A replacement — a new version of a paper already in the archive.
.ds-badge--cross
A cross-listing — the paper’s primary category is elsewhere.
.ds-badge--wdr
A withdrawal. Darkest of the four, because it is the one that changes what a reader gets.
  • The abbreviation is the label. It is what the moderation queue has always shown, and expanding it would widen the column for no gain.
  • The palette is its own, not the status palette. A submission type is a category. “New” is not success and “Wdr” is not an error, and painting them with the status colours would say something untrue about the queue. The four carry --ds-badge-* tokens.
  • Today only internal tools show one — see table styles for badges in a live queue. The component is not limited to submissions, and it is in the shared stylesheet, so any surface that needs a type marker in a dense row can use it.

Accessibility essentials

  • Use the element that matches the job. A tag that only labels is a <span>. A tag that goes to a listing is an <a> with a real href. A tag that does something on this page is a <button type="button">. Hover and focus styles come from the element, so a <span> with a click handler has no focus ring and cannot be reached from the keyboard.
  • Uppercase is applied with CSS, never typed. The underlying text then stays correct for copy-and-paste, in-page search, and screen readers.
  • Keep the case of every category and identifier. Put .ds-tag--keep-case on any tag that holds a category name or an arXiv ID, so that physics.optics is never shown as PHYSICS.OPTICS.
  • Color is never the only signal. The label’s own words carry the meaning. A negative or removed state says so in text, not only in red.
  • Name the remove control. Every .ds-tag-remove holds a <span class="is-sr-only"> that says what it removes, such as “Remove cs.AI”, and the ✕ glyph sits in a span with aria-hidden="true". Do not use title or aria-label for this, because page translation tools skip attributes.

Rules

Three small labelled things, and which is which

The system has three components that are all “a bit of text in a small box”. They are not interchangeable, and the difference is what the text is, not how it looks.

ComponentShowsWhereLooks like
.ds-tag What a thing is — a subject category, a topic, a state. Both surfaces.
math.CO Withdrawn
.ds-badge A type. Today that means a submission's type in arXiv Check — new, replacement, cross-list, withdrawal — but the component is not limited to submissions; any other kind of type could use it. Internal tools — table styles.
New Rep Wdr Cross
.ds-panel-label The label half of a label/value pair, or a small section heading. Not a box at all. Both surfaces — typography. Submitted

The “pill menus” on HTML papers are not tags. Why?

They are not tags, they are actions — copy a permalink, open the figure large, read the alt text. You can see it without knowing the markup: a tag is a filled pill with a coloured background, and those are white with icon labels. They are documented on Buttons, under Small actions attached to content.

Nor are the inline chips in a paper

A citation marker like [12] or an equation number like (3.4) is not a tag either, and for a different reason: the author wrote it. It comes out of the LaTeX source, and arXiv only makes it navigable — the citation becomes a link, the equation number becomes an anchor. A tag is something arXiv adds to describe content. An inline chip is content, which we layer on top of and never edit (DESIGN-POLICIES).

Why the tag is a pill and the badge is a rectangle

Not decoration. A tag is a standalone object — it may be a link, it may carry a remove control, and it sits in open space where its rounded ends read as one unit. A badge sits inside a dense table row where a pill’s horizontal padding costs column width that the title needs more. Same idea, different pressure.

Not the same as a type badge. .ds-badge stays a 3px rectangle: a compact code in a dense data grid. A tag is a discrete labeled object in a wrapping list.

Why the badge has its own colours rather than the status palette

Because a submission type is a category, not a status. “New” is not success and “Wdr” is not an error — painting them with the status colours would say something untrue about the queue. They carry their own tokens, --ds-badge-*.
