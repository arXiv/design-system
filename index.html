Smileybones: the arXiv design system

These pages hold arXiv's approved patterns for front-end interfaces built around accessibility, usability, and our brand. They hold design tokens, component specs, typography, color, accessibility requirements, interactive pattern references, and more. Optimized for both human and agent digestion, the aspirational dream is that you give your agent your content, goals, and the link to the DS and say "make it so". To help us get there, share your feedback and implementation experiences so we can improve the DS together.

Components

Colors

The full arXiv palette, rendered.

Dark mode

In the design system, every colour comes from a token and the tokens flip in each mode.

Typography

arXiv sets all text in the IBM Plex family with STIX Two Math for notation.

Spacing

Every gap on arXiv pages comes from one spacing scale.

Icons

The design system uses the Lucide icon set which is open source, community supported, and available for both commercial and non-commercial use under the ISC license.

Buttons

Each arXiv button family shares the same mechanical spec, with color used to differentiate by context: Open Blue for public pages and Access Lime for internal tools.

How the repository is organized

Build only from the canonical folders. Everything else in the repository is for exploring ideas, planning, or testing. AI coding agents start at AGENTS.md, which holds the same map with a reading order.

Folder Status What it holds
docs/ Canonical The documentation: rules, pattern pages, and the stylesheets.
docs/assets/ Canonical, for images arXiv's official image library: logos, illustrations, backgrounds, and photos. Other repositories link to these files by URL.
templates/ Canonical, for markup The shared head, header, and footer that other arXiv apps install. Their styles come from docs/.
verification/ Testing The automated checks, audits, design reviews, and agent tests.
whiteboard/mockups/ Exploration Whole-page explorations in progress. A pattern moves into docs/ when it is stable.
whiteboard/planning/ Exploration The backlog, proposals, and decision logs.
blog-theme/ Separate project A packaged copy of the blog.arxiv.org theme, a separate project that extends the design system.
